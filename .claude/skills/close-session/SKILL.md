# セッションを閉じる

**目的**: 出したものが実装と食い違ったまま残らないこと、外に出したもの（検証ビルド・
掲載用の写真・ブラウザ・端末の設定）を戻し忘れないこと、次のセッションが状況を
再構築せずに済むこと。

だいどこの `close-session` を移植した（2026-08-28）。**さいえん手帳の実情に合わせて
書き直してある** — サーバーは動いておらず（#150）、BYOK は導線が断たれている（WBS 2.9b）。
代わりに**ストア掲載物・タグ・掲載用写真の差し替え**の後始末が要る。

`review-log` は「レビュー指摘を**どこへどう**書くか」。この Skill は
「**閉じるときに何を確かめるか**」。記録の書き方はあちらへ委譲する。

---

## 1. 触ったものの棚卸し

```bash
git status --short                          # 未コミットの取りこぼし
git log --oneline origin/develop..HEAD      # このセッションで積んだもの
gh pr list --state open --json number,title --jq '.[] | "#\(.number) \(.title)"'
git status -sb | head -1                     # upstream がどこを指しているか
```

- **他セッションの変更を巻き込まない。** `.github/workflows/ci.yml` のように
  別セッションが触っているファイルが `M` で残ることがある。**`git add -A` は使わず**
  自分が触ったパスだけを staging する
- **`HANDOFF.md` は未追跡のまま**運用している。リポジトリには入れないが、
  **閉じる前に現状へ更新する**（§7）

## 2. 掲載用の写真を戻したか（**最優先**）

```bash
node scripts/release/use-store-photos.mjs --status
```

**「元のまま（配布用と同じ）」以外が出たら、コミットする前に `--restore`。**
差し替えたまま放置すると、**掲載用の写真が配布物に入る**。
`assets/` に置いた画像は `require()` で静的解決され、実行時フラグでは止まらない
（CLAUDE.md §4b）。

## 3. 端末・エミュレータ・ブラウザの後始末

**忘れやすい順**。該当するものだけ。

| 出したもの                       | 戻し方                                                                                          |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| **検証ビルドが入ったままの実機** | **必ず申し送る。** ローカル署名版は Play 版で上書きできず、戻すには消すしかない（データが飛ぶ） |
| エミュレータ                     | `adb -s emulator-XXXX emu kill`。**他プロジェクトの AVD は落とさない**（`emu avd name` で確認） |
| ブラウザ（CDP）                  | `chrome-saien-profile` を起動したままにしない。一時 HTTP サーバーを立てたなら**必ず停止・削除** |
| SystemUI デモモード              | 撮影スクリプトが戻すが、途中で落ちたら残る                                                      |
| `adb reverse`                    | `adb reverse --remove-all`（本番構成の検証を壊す）                                              |
| 画面・電源の設定                 | `svc power stayon false` / `screen_off_timeout` を元へ                                          |
| scratchpad の一時ファイル        | **鍵・トークン・個人の写真を書いたものは消す**                                                  |

> **実機の状態は必ず申し送る。** 2026-08-27 の時点で AQUOS には
> **ローカル署名の 1.2.0** が入っており、Play 版へは戻せない状態だった。
> 検証用と普段使いの端末を混ぜると、こうなる。

## 4. 状態は**実物に聞く**（ドキュメントを実態と思わない）

**リリース済みか・公開されたか・審査が通ったかを、リポジトリの文書から答えてはいけない。**
文書は書かれた時点の記録で、ストアの状態は文書と無関係に進む。

```bash
node scripts/release/store-status.mjs        # Play / App Store の両方（読み取りのみ）

# ログイン不要で公開版だけ見たいとき
curl -s "https://itunes.apple.com/lookup?bundleId=com.saientecho.app&country=jp"
```

> **実際にやらかしている。** 2026-08-27 に「1.2 はもう出ていたか」を聞かれ、
> 掲載スライドのコメントや過去の引き継ぎにある「1.2 で公開予定」を根拠にしかけた。
> **あれはすべて予定の話**で、版としては存在していなかった。ストアに聞いて確定した。

確かめた結果が文書と食い違ったら、**文書を直してから報告する**。

## 5. ドキュメントと実装の整合性

**機能を移設・置換・削除したときは必ず回す。** 設計書は移設に追従しない。

### 5-1. 機械的な突き合わせ

```bash
# docs / Skill が挙げるファイルが実在するか（リネーム・削除の取りこぼし）
grep -rhoE '\b(apps/mobile|scripts)/[A-Za-z0-9_./()\[\]-]+\.(ts|tsx|js|mjs|py)' \
  docs/*.md .claude/skills/*/SKILL.md | sort -u \
  | while read f; do [ -e "$f" ] || echo "MISSING: $f"; done

# 完了した Issue が open のまま残っていないか（CLAUDE.md §3 の再発防止）
gh issue list --state open --limit 40 --json number,title --jq '.[] | "\(.number)\t\(.title)"'
```

> **「存在しないパスを指す参照」は 1 日で 2 件出たことがある**（振り返りの宿題 3）。
> **完了 Issue の閉じ忘れも実績がある** — 2026-08-27 に #30 が open のまま見つかった。
> `Closes #N` は**既定ブランチ（develop）への PR でしか自動で閉じない**。

### 5-2. 目で見る突き合わせ（grep で出ない）

機能を置き換えたら、**その機能を語っている文を全部**洗う。実際に食い違っていたもの:

| 種類                     | 例                                                                         |
| ------------------------ | -------------------------------------------------------------------------- |
| WBS の完了条件           | 4.4 が「スライダー」のまま（作れないと確定して落としていた）— 2026-08-27   |
| 「できない」と書いた記述 | app-ads.txt「現状は設置できない」が設置済みのまま残っていた — 2026-08-27   |
| 手順の前提               | `expo run:ios` に `--device` が無く、そのまま実行すると固まる — 2026-08-28 |
| 掲載文と実装             | 資材の写真読み取りは未実装（#139）。**盛った文言を出さない**               |

`CLAUDE.md` §2 の索引を上から眺めて、**触った機能に触れている文書**を選ぶ。

## 6. 分かったことを残す（→ `review-log` / 手順書）

このセッションで**手が止まった場所**を思い出すのが早い。**20 分溶かした所には
たいてい記録すべきものがある。**

- レビュー指摘は `review-log`（`docs/レビュー記録/`）
- **手順の罠は、その手順書自身に書く**。別ファイルに書くと読まれない
- **「試して駄目だった」も残す。** 次の人が同じ時間を溶かさずに済む
  （例: `eas build --local` は Apple に弾かれる / `xcodes list` の `[Universal]` は嘘）

**本当に無ければ「記録すべき発見は無かった」と報告に明記**して終える（黙って終えない）。

## 7. `HANDOFF.md` を現状へ更新

未追跡のまま運用している。**次のセッションが最初に読む**ので、ここが古いと誤誘導になる。

必ず直す項目:

- **いまどこにいるか**（工程表・止まっている理由）
- **承認待ちのもの**（選択肢とこちらの推奨）
- **公開状況**（§4 で実物に聞いた結果）
- 端末・ブラウザ・他セッションの状態

## 8. 申し送り（報告に必ず書く）

- **未完了**と、その理由（判断待ち / ブロック要因 / スコープ外にした）
- **利用者の判断を待っているもの**（選択肢と、こちらの推奨）
- **配信されたか。** develop や main にマージしただけなら
  **「アプリはまだ配信されていない」と明記する**
- 触った端末・ブラウザ・他セッションの状態（§3 で戻せなかったもの）
- **期限のあるもの**（例: AdMob の再確認日、Xcode の入手期限）

## 9. 品質ゲート（PR を出すなら）

```bash
pnpm --filter mobile exec jest        # ルートから npx jest すると config が違って全滅する
npx prettier --write <触ったファイル>
```

- **pre-commit が重い**（prettier → lint → typecheck → 全テストで 5〜10 分）。
  **コミットは `run_in_background: true` で回す**
- **リリースのタグは提出より前に打つ**（docs/リリース手順.md §4b）。
  「公開されたら」は末尾なので落ちる
