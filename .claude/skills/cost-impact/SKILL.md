# コスト影響分析（cost-impact）

**コストは設計の一部。** 機能を足すとき「動くか」だけでなく
「誰がいくら払うか」を同じ PR で決める。
1.1 のリリース直前（2026-08-23）に「維持費は変わっていないか」と聞かれて
初めて分析した反省から、**聞かれる前に出す**ための手順。

## いつ使うか（フックが督促する）

`scripts/agent/lib/docs-map.mjs` の `cost-impact` 規則に当たるファイルを編集すると、
PostToolUse / Stop フックが本 Skill と §5 の更新を督促する。対象:

| 触るもの                    | 典型例                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------- |
| **推論の入口**              | `apps/mobile/src/services/{garden-consult,harvest-read,planting-identify}.service.ts` |
| **無料枠・リワード**        | `usage.service.ts` / `identify-credit.service.ts` / `ad-reward*.ts`                   |
| **サーバー接続先・広告 ID** | `apps/mobile/src/config.ts` / `apps/mobile/eas.json`                                  |
| **サーバー側の上限**        | `rate-limit.ts`（だいどこ側。さいえん手帳の `apps/server` は死んでいる — #150）       |

フックに当たらなくても、**設計メモに「サーバーへ送る」「推論する」「広告で賄う」の
いずれかが書かれたら**この Skill を回す。

## 出す数字は 3 つ

| 数字                      | 出し方                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1 回あたり**            | 入力トークン（画像 1024px ≒ 1,100 + プロンプト）× 入力単価 + 出力トークン × 出力単価。実測があればそれを正とする（consult ¥0.35 / harvest・identify ¥0.07 — 2026-08-21 実測） |
| **1 人あたり / 月**       | 無料枠（**生涯 1 回**・#151）+ リワードで解放される回数 × 1 回あたり。**無料枠は「一番高い呼び出し」の単価で見積もる**（枠が共用なので、ユーザーは高いほうに使える）          |
| **サーバー側の天井 / 月** | `GLOBAL_DAILY_LIMIT × 1 回あたり × 30`。**これが実コストの上限**で、1 人あたりの数字より重要                                                                                  |

固定費（Railway / Apple Developer / Play / ドメイン）は**増減が無いことも明記する**。
「変わらない」は分析した結果であって、分析しなかった結果ではない。

## 手順

1. **現状の上限を実物で読む**（値はチャットに出さない — `--json` で変数名だけ拾う）

   ```bash
   cd <だいどこの worktree> && railway variables --json | python -c "
   import json,sys; d=json.load(sys.stdin)
   print([k for k in d if 'LIMIT' in k])"
   ```

   **設定されていないプールはコード既定値が効いている**（`rate-limit.ts` の `globalDefault`）。
   2026-08-23 時点で明示されているのは `INFER_GLOBAL_DAILY_LIMIT` だけで、
   菜園系 3 プールは既定値（100 / 500 / 300）が暗黙に効いていた（#157）。

2. **変更後の 3 つの数字を出し、`docs/インフラ・NW構成設計.md` §5 の表と突き合わせる**。
   差分があれば §5 に小節を足す（日付つき）。**既存の行を書き換えず、追記で履歴を残す**。

3. **PR 本文に「コスト影響」節を書く。** 増えないなら「増えない（理由）」と書く。
   `hook-stop-docs-guard` はこの Skill と §5 の更新が無いと停止を止める。

4. **ストア提出前にもう一度回す。** 提出後は上限を下げる以外の手が無い。

## Gotchas（実績つき）

- **上限 `0` は「無制限」になる**（`if (globalLimit > 0 && …)` の短絡・#157）。
  塞ぎたいなら **`1`** を設定する。「使わせたくないから 0」は逆効果。
- **エンドポイントはアプリが呼ばなくても生きている。** 認証なし・レート制限のみなので、
  デプロイした時点で天井に乗る。**次版まで使わない経路は上限で塞ぐ**
  （`/garden/identify` を 1.1 で開けたまま出した — #157）。
- **無料枠が共用なら、単価は最大のもので見る。** #151 以前は「1 日 1 回」が
  実質 ¥0.35/日（相談の単価）で赤字だった。枠を分けるか、高い呼び出しに合わせる。
- **Gemini の単価は変動する**（2026-07-02 に 2 倍）。`docs/インフラ・NW構成設計.md` §5 の
  前提行を見て、古ければ先に更新する。
- **固定費の「増えない」も根拠を書く。** Apple Developer $99/年は v1.0（2026-08-15）で
  発生済み、Railway はだいどこ共用で決定⑨。新サービス・新インスタンスを足していないなら
  そう書く。
