# Harness Auditor

`.claude/` 配下のスキル・サブエージェント・フック・MCP 設定を Harness 7軸で監査する。

判定の一次ソースは Anthropic 公式仕様であり、本スキルの軸はその上に載る評価観点にすぎない。**仕様準拠そのものの機械チェックは `claude-customization-check` スキル**（`node scripts/agent/validate-claude-customizations.mjs`）で行い、本スキルは「仕様には合っているが品質が低い」箇所を人手で採点する。先に機械チェックを通してから採点すること。

## 監査手順

1. `node scripts/agent/validate-claude-customizations.mjs` を実行し、仕様違反（ERROR）をゼロにする
2. 対象スキル/エージェントの本文を読む
3. 以下の 7軸それぞれを 0〜3 で採点する
4. 総合スコアと改善提案を生成し、検証ループを通す

### 軸1: Tool Coverage（ツール網羅性）

- [ ] `description` が「何をするか」＋「いつ使うか」を含み、LLM がルーティングできる
- [ ] 関連スキル間で `description` のキーワードが競合していない
- [ ] サブエージェントの `tools` が役割に対して適切に絞られている（読み取り専用の agent に Edit/Write がない等）
- [ ] MCP を使うサブエージェントは `mcpServers` frontmatter を持つ
- [ ] 起動制御（`disable-model-invocation` / `user-invocable` / `paths`）が意図どおり設定されている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸2: Context Efficiency（コンテキスト効率）

- [ ] SKILL.md が 500 行以内
- [ ] **`description` + `when_to_use` の合計が 1,536 文字以内**（超過分はスキル一覧で切り捨てられ、ルーティングに効かない）
- [ ] 参照ファイルへの言及が条件付き（「いつ読むか」が明示されている）
- [ ] Progressive Disclosure に従い、大量の参照情報が `references/` に分離されている
- [ ] `assets/` テンプレートが本文から参照されている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸3: Quality Gates（品質ゲート）

- [ ] 検証ループまたはバリデーション手順が存在する
- [ ] `settings.json` の PostToolUse / Stop フックで品質チェックが自動実行される
- [ ] チェックリストが含まれる
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸4: Memory Persistence（メモリ永続化）

- [ ] Gotchas セクションが 3 項目以上
- [ ] Gotchas が**具体的**（このリポジトリでしか起きない事象を書いている）
- [ ] 学びをファイルに書き出す指示がある、または agent に `memory` frontmatter が設定されている
- [ ] コンパクション耐性（重要な中間結果のファイル保存）が考慮されている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸5: Eval Coverage（評価カバレッジ）

- [ ] 出力の検証基準が明示されている
- [ ] 検証ループに失敗時のリカバリ手順がある
- [ ] CI またはフックで機械検証が回っている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸6: Security Guardrails（セキュリティガードレール）

- [ ] 禁止事項が明示されている
- [ ] 不可逆・外向きの操作に承認ゲート（HITL）が置かれている
- [ ] `allowed-tools` / `disallowed-tools` / `permissionMode` が過剰な権限を与えていない
- [ ] 機密情報の取り扱いルールが定義されている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

### 軸7: Cost Efficiency（コスト効率）

- [ ] 本文が簡潔（エージェントが既に知っている一般論を書いていない）
- [ ] このリポジトリ固有の情報のみ記載されている
- [ ] デフォルトが明示され、選択肢が最小化されている
- [ ] 重い処理のサブエージェントに `model` / `effort` が適切に設定されている
- **スコア**: 0=未対応 / 1=基本対応 / 2=良好 / 3=優秀

## 出力テンプレート

固定フォーマットの監査レポートは `examples/harness-audit-report.md` を参照する。

```markdown
# Harness Audit Report: <対象>

## サマリー

- **総合スコア**: <合計>/21
- **成熟度**: <Beginner|Intermediate|Advanced|Expert>
- **仕様違反(機械チェック)**: <ERROR 件数> / <WARN 件数>

## 軸別スコア

| #   | 軸                  | スコア | 判定   |
| --- | ------------------- | ------ | ------ |
| 1   | Tool Coverage       | /3     | <状態> |
| 2   | Context Efficiency  | /3     | <状態> |
| 3   | Quality Gates       | /3     | <状態> |
| 4   | Memory Persistence  | /3     | <状態> |
| 5   | Eval Coverage       | /3     | <状態> |
| 6   | Security Guardrails | /3     | <状態> |
| 7   | Cost Efficiency     | /3     | <状態> |

## 改善提案（優先度順）

1. 🔴 **[軸名]**: <具体的な改善アクション>
2. 🟡 **[軸名]**: <具体的な改善アクション>
3. 🟢 **[軸名]**: <具体的な改善アクション>
```

**判定はブロッキング優先**: 仕様違反(ERROR)が 1 件でもあれば、スコアに関わらず不合格として先に直す。

## 成熟度基準

- Beginner: 0–7、またはいずれかの軸がスコア 0
- Intermediate: 8–14、全軸でスコア 1 以上
- Advanced: 15–18、全軸でスコア 2 以上
- Expert: 19–21、全軸でスコア 2 以上かつ半数がスコア 3

## Gotchas

- **`.github/skills` と `.claude/skills` は別物**。本リポジトリは両方持っているが、Claude Code が読むのは `.claude/` 側だけ。`.github/` 側は GitHub Copilot 用で、採点対象を取り違えると「全部 0 点」になる
- 7軸フレームワーク自体は Anthropic 提唱のものではない（出典: coreclaw）。**仕様準拠の判定に使ってはいけない** — 仕様は公式ドキュメントと `claude-customization-check` が持つ
- `description` の評価は「人が読んで分かるか」ではなく「LLM がルーティングできるか」で行う。日本語の説明文は読みやすくてもキーワードが弱いことがある
- Gotchas は「量」より「具体性」。どのリポジトリにも当てはまる一般論しか書いていない場合はスコア 1 止まり
- `assets/` や `references/` が存在するのに本文から参照されていない場合は減点（死蔵アセット）。逆に「あるべきなのにない」ケースも指摘対象
- 本リポジトリの `.claude/` はだいどこからの移植であり、**さいえん手帳と無関係な記述が残っている**（レシピ・ストア掲載・AdMob など）。採点時に「このリポジトリ固有か」を軸7で見る際は、移植残骸を減点対象として扱う

## 検証ループ

1. 監査レポートを生成する
2. 以下を確認する:
   - 全 7 軸にスコアが付与されているか
   - 改善提案が具体的かつ実行可能か（「改善する」ではなく「どのファイルの何をどうする」か）
   - 成熟度判定が基準と整合しているか
   - 機械チェックの ERROR 件数がレポートに反映されているか
3. 不整合があれば修正して再生成する
4. 整合後のみ完了とする
