> **4.15 の作物登録モードは春の獲得期に直撃する。** 苗を買って植えるときにラベルを
> 撮るだけで栽培登録が終わる。**品種名はユーザーが打てない**(「アイコ」「桃太郎」は
> 固有名詞で読みも分からず `nameReading` も埋まらない)。
> ML Kit・expo-camera は 2.9d で「使い道が無い」として消したが、**種袋・肥料袋の
> 読み取りがまさにその使い道だった** — ただし戻すのは ML Kit ではなく**サーバー側**。
> ネイティブ依存を戻さずに済み、分類と数量まで構造化するのは LLM の方が得意。
>
> **#136 の容器診断は 4.15 の 1 モードとして作る。** 単発の機能にすると
> 4 つ目以降が安くならない。
>
> **4.12 は「月で足りる」という当初の決めを覆す。** `crop-master.ts` 冒頭のコメントも
> 一緒に書き換えること。**週(1 週目/2 週目)ではなく旬**を推す — 日本の農業資料が
> ほぼ旬で書かれており、週で切ると**出典に無い粒度を自分で作る**ことになって
> R08 の「出典明記」が成り立たなくなる。
>
> **4.13 は新規ではなく R20(5.2 天気連携)。** 起票時に既存の #34 を見落として
> #136 を立ててしまった(2026-08-18 に気づいて #34 をクローズ)。R20 の定義は
> 「**抑制**(雨予報の日はリマインダーを出さない)と**促進**(晴天続き・高温予報で前倒し)の
> 両方向。**霜注意・強風注意の警告も含む**」で、設計は抑制と促進を満たしていたが
> **霜・強風を落としていた**。既存 Issue を読んでいれば最初から入っていた。
>
> **予報と警報で区分の細かさが違う**(2026-08-18 実測)。予報(天気・降水確率・気温)は
> **一次細分区域**まで(静岡県 = 中部/東部/西部/伊豆の 4 つ・市区町村の予報は存在しない)、
> 週間予報はさらに粗く**県まるごと**。一方**警報・注意報は市町村単位**
> (静岡県で 42 区分・7 桁コード)。**霜注意・強風注意はこちら**なので、
> 市区町村を選ばせるのは体験上だけでなく**機能上も要る**。
>
> **4.13 で Open-Meteo は使えない**(2026-08-17 実測)。無料枠の条件が
> 「広告を表示するアプリ」を商用扱いにしており、さいえん手帳は AdMob で広告を出している。
> また、気象庁の予報を**そのまま見せる**のと**独自の予想を発表する**のは別物なので、
> 言い回しを決める前に気象業務法を確認すること。霜も**注意報を伝えるのが本筋**で、
> 最低気温からの推定は補助に留める。

### T2 で書き直す理由

`e2e/android-e2e.mjs` は uiautomator dump ベースの仕組みとしては流用できるが、

**CI では走らせない。** 端末が要るうえ 1 回数分かかる。リリース前と、

### I1 で分かったこと(2026-08-13)

- **AdMob のユニット ID はプラットフォームごとに別物。** Android の ID を iOS で
  使っても配信されない。`config.ts` の `platformAdUnit()` で無印 = Android・
  `_IOS` 付き = iOS として解決する(だいどこから移植)
- **未設定のユニットを公式テスト ID へ落としてはいけない。** 落とすと
  **本番ビルドにテスト広告が出る** — iOS のユニットを作る前に iOS ビルドを回すと
  実際にこの状態になる。テスト広告の本番配信は AdMob のポリシー違反にあたる。
  既定を「空なら出さない」にし、検証時だけ `EXPO_PUBLIC_ADMOB_ALLOW_TEST_UNITS=true`
  を明示する立て付けにした(3 形式すべて)
- **iOS の `buildNumber` は同一バージョン内で一意かつ増加**でなければならない
  (App Store Connect の制約)。だいどこが踏んだので `versionCode` と揃える運用にする
- **Apple はアプリアイコンに透過・アルファチャンネルを認めない。** 背景を敷いても
  sharp の既定は RGBA のままなので、`icon.png` / `favicon.png` は生成時に flatten する
  (透過が要るアダプティブアイコン前景・スプラッシュは対象外)

### 3.7 / 3.8 で分かったこと(2026-08-11)

**`expo prebuild` は追記・マージしかしない。** app.json から `blockedPermissions` を
外しても、生成済みマニフェストの `tools:node="remove"` は残る。`--clean` で
android/ を作り直すまで AD_ID が削除されたままだった(WBS 2.9d の
MainApplication と同じ罠)。**権限を「外す」変更をしたら --clean が要る。**

**APK の権限は aapt で実際に確認する。** マニフェストのソースだけ見ても、
ライブラリのマージ結果は分からない。確認したところ、宣言すべきでないものが
3 つ入っていた(下表)。

| 権限                                | 出所                               | 対応                           |
| ----------------------------------- | ---------------------------------- | ------------------------------ |
| `com.android.vending.BILLING`       | RevenueCat → billingclient         | **ブロック**(下記)             |
| `RECORD_AUDIO`                      | expo-image-picker(動画撮影用)      | ブロック(動画は未使用)         |
| `SYSTEM_ALERT_WINDOW`               | RN の開発用オーバーレイ            | ブロック                       |
| `USE_BIOMETRIC` / `USE_FINGERPRINT` | expo-image-picker の画像クロッパー | 残す(外すと切り抜きが壊れうる) |

**BILLING が一番重い。** 収益化方針の調査どおり、Play で「課金あり」と扱われると
個人開発者はトレーダー扱いになり**氏名と住所がストアに公開される**。
v1.0 を広告のみにしているのはそれを避けるため。RevenueCat が v1.0 で一度も
初期化されない(API キーが空 → stub)ことを確認したうえで外した。**4.3 で解除する。**
