## 前提（I5 から変わっていない）

- リポジトリルートで `pnpm install`（`.npmrc` が `node-linker=hoisted`。`apps/mobile` 内で実行しない）
- Xcode + Command Line Tools・CocoaPods・Node/pnpm

## 手順

```bash
# 1) シミュレータ起動（既定は iPhone 16 Pro Max = 6.9"/1320x2868）
xcrun simctl boot "iPhone 16 Pro Max" ; open -a Simulator

# 2) ストアショット用ビルド（サンプルデータ有効・コーチマーク無効・広告 OFF）
LANG=en_US.UTF-8 \
  EXPO_PUBLIC_ENABLE_SAMPLE_DATA=1 EXPO_PUBLIC_DISABLE_COACH_MARKS=1 \
  pnpm --filter mobile exec expo run:ios --configuration Release

# 3) オンボーディング（地域選択）を一度済ませる
#    未完了だと、どのルートを開いても「ようこそ」画面が出てしまう

# 4) 取得（9:41・満充電にステータスバーを固定）
node scripts/release/capture-ios-screenshots.mjs
```

> **撮れたかはファイルサイズで判断する（2026-08-22 に Android で 8 枚全滅）。**
> 中身が出ていれば 100KB 前後〜、**20KB 前後ならローディングのスピナーしか写っていない**。
> `capture-ios-screenshots.mjs` の既定待ちは 6 秒 → **12 秒**に上げてあるが、
> それでも小さいときは `--wait` をさらに伸ばして撮り直す。

### I5 で踏んだ罠（再掲・全部そのまま生きている）

- **`LANG` を必ず渡す。** ロケール未設定の Mac では CocoaPods が
  `Unicode Normalization not appropriate for ASCII-8BIT` で落ちる。Expo は pod install の
  失敗を警告扱いのまま xcodebuild へ進むので、**「The sandbox is not in sync with the
  Podfile.lock」まで行って初めて気付く**
- **`EXPO_PUBLIC_ADMOB_*` は付けない。** 掲載物にテスト広告が写り込む事故を防ぐ
  （未設定なら広告は出ない設計。`config.ts` の `ADMOB_ENABLED`）
- **URL 確認ダイアログ（iOS 17+）で手が要る。** `simctl openurl` でカスタムスキームを開くと
  SpringBoard が「"さいえん手帳" で開きますか?」を出し、**「開く」を押すまで起動しない**。
  毎回は出ず、出たり出なかったりする。スクリプトは前面に出るまで待ってから撮るので、
  待ちに入ったらシミュレータ側で押す（既定 90 秒でタイムアウト → `FAILED` で非ゼロ終了）

### 決定（2026-08-22・Windows 側で確定）

**8 枚目として `08-harvest-reads` を足す。差し替えない。**

```
08-harvest-reads   写真から記録（読み取り待ち）  route: harvests/reads
```

- **差し替えない理由**: 既存 7 枚は 1.1 でも実物と合っている。下の
  「中央タブが『追加』から『撮る』に変わる」は **1.1 では起きていない**
  （タブは「追加」のまま。中央タブの変更は #143 の残りスコープで、1.1 に入っていない）。
  掲載物とずれているのは「新機能が写っていない」ことだけ
- **足す位置**: 末尾。Play / ASC ともスマホ用は最大 8 枚なので枠に収まる
- **写す状態**: サンプルデータの `seedHarvestPhotoReads`（読み取り済み 1・待ち 1）。
  **ルートを開くだけで撮れる**ので、下の「ディープリンクだけでは撮れない」問題は解消済み
- 両スクリプト（`capture-store-screenshots.mjs` / `capture-ios-screenshots.mjs`）に
  追加済み。Mac 側は `--shots 08` だけ回せば足りる

> **1.1 の掲載順は変えていない。** 新機能を先頭寄りに出すかは掲載の判断で、
> 変えるならファイル名の振り直しが要る（順序 = ファイル名）。今回は見送った。

> **ディープリンクだけでは撮れない画面がある。** スクリプトはルートを開いて撮る作りだが、
> 写真ベースの記録は**対話的**（撮る → 下書き → 確認 → 保存）なので、
> ルートを開いただけでは「写真から数量が入った状態」が写らない。
> **サンプルデータ（`seed.ts`）側に、解析済みの収穫記録と未解析キューを用意する**
> ことが前提になる。これは実装（#143）のスコープに含める。

## サイズ（I5 で ASC の実フォームを見て確認済み）

バージョンページのアップロード枠は **6.5 インチ表記**で、受理サイズは
`1242×2688 / 2688×1242 / 1284×2778 / 2778×1284`。
16 Pro Max の **6.9"（1320×2868）はメディアマネージャー経由でアップロードできる**
（枠の右上「メディアマネージャーですべてのサイズを表示」）。

- **既定のまま 16 Pro Max で取る**
- 6.9" が弾かれた場合のフォールバックだけ用意:
  `xcrun simctl boot "iPhone 16 Plus"`（1284×2778 = 受理サイズ）で `--udid` を付けて取り直す。
  **先回りして両方は取らない**（承認対象が倍になる）
