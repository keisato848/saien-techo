## A. あなたにしかできない作業

### A-1. AdMob（WBS 3.7 の残り）

現状は **Google 公式のテスト ID** が入っていて、テスト広告が出る状態。実 ID に差し替える。

1. AdMob アカウントを作る（Google アカウントで登録）
2. アプリを登録する（Android / パッケージ名 `com.saientecho.app`）
3. 次の 2 つを発行して控える
   - **アプリ ID**（`ca-app-pub-XXXXXXXX~YYYYYYYY` の形）
   - **アプリ起動（App Open）広告ユニット ID**（`ca-app-pub-XXXXXXXX/ZZZZZZZZ` の形）
4. こちらに渡す → `app.json` と env に入れて焼き直す

```
app.json  → plugins > react-native-google-mobile-ads > androidAppId
ビルド時  → EXPO_PUBLIC_ADMOB_APP_OPEN_UNIT_ID=ca-app-pub-.../...
            EXPO_PUBLIC_ADMOB_ENABLED=true
```

> **実 ID を入れたビルドで自分の広告を何度もタップしないこと。** 無効なトラフィックとして
> アカウントが停止されることがある。動作確認はテスト ID のままで済ませる。

### A-2. プライバシーポリシーの公開 URL

Play Console は **URL** を要求する。原稿は `docs/プライバシーポリシー.md` にある。

- 独自ドメインは**取らない決定**（インフラ設計 D2）なので、GitHub Pages か Gist が候補
- 公開したら URL をこちらに渡す（掲載情報にも載せる）

### A-3. Play Console での入力

- **データセーフティ申告** — `docs/store/google-play/data-safety.md` を見ながら入力
- **掲載情報** — `docs/store/google-play/listing-ja.md` が正。
  サービスアカウント JSON（既定 `C:/secure/play-service-account.json`）を置けば
  `node scripts/release/update-play-listing.mjs` で流し込める
- **コンテンツのレーティング**アンケート
- **対象年齢・広告の有無**の申告（**広告あり**）
- **クローズドテスト**の設定（判断④: 個人アカウントはテスター数 × 14 日の要件がありうる）

### A-4. 署名

現状のリリースビルドは**デバッグ鍵で署名**されている（`signingConfig signingConfigs.debug`）。
サイドロード用には問題ないが、**Play 提出には本番鍵が要る**。

- Play App Signing を使う前提で、アップロード鍵を作る
- 鍵とパスワードの保管場所を決める（**紛失すると更新できなくなる**）
