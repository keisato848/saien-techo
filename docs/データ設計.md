# さいえん手帳 — データ設計

> 作成: 2026-08-03（WBS 1.3）
> ステータス: v1（v0.1 Alpha 向け）
> 移植元: `docs/参考-daidoko/データ設計.md`（だいどこ）。流用マッピングは `docs/要件定義.md` §7.2

---

## 1. 設計方針

- **ローカルファースト** — 全データは端末内 SQLite に保持する。サーバーは AI 推論のみで、データを持たない（`docs/インフラ・NW構成設計.md`）
- **オフライン完結** — ネットワーク不在でもすべての読み書きが動く
- **タイムラインの基本単位は作業ログ** — `care_logs` が記録の中心。カレンダー・ギャラリーもこれを見る
- **収穫は独立エンティティ** — 数量・単位を持ち、アルバム（R07）と統計（R18）の対象になるため `care_logs` から分離する
- **作物はマスター参照 + 自由入力の併用** — マスターにない作物も登録できるよう、`crop_id` を nullable にして `crop_name` を必ず持つ
- **タイムスタンプは TEXT（ISO 8601）** — だいどこの既存テーブルがこの形式のため揃える。epoch ms との混在は避ける
- **だいどこのスキーマとは当面併存** — 未リリースだが UI が recipes 系を参照しているため、WBS 1.5（栽培 CRUD）で差し替えるまで両方のテーブルが存在する。recipes 系の削除は 1.5 完了後の別タスク

### 移行方針（重要）

`migrate.ts` の版管理に **v8 として追加**する。だいどこのテーブルは DROP せず残す。

| いつ            | 何をする                                                               |
| --------------- | ---------------------------------------------------------------------- |
| WBS 1.3（本書） | plantings 系を **追加**。recipes 系はそのまま                          |
| WBS 1.5         | UI を栽培 CRUD へ差し替え                                              |
| 1.5 完了後      | recipes / ingredients / steps / recipe_revisions / recipe_tags を DROP |

こうする理由は、CLAUDE.md §5 が「マージ前に必ずエミュレーター/実機で動作確認する」と定めているため。先に recipes を落とすと 1.5 完了まで動作確認できる状態が作れない。

## 3. エンティティ詳細

### 3.1 crops（作物マスター）

| 列                          | 型   | 制約     | 説明                                                     |
| --------------------------- | ---- | -------- | -------------------------------------------------------- |
| `id`                        | TEXT | PK       |                                                          |
| `name`                      | TEXT | NOT NULL | 作物名（トマト）                                         |
| `name_reading`              | TEXT |          | 検索用のひらがな読み                                     |
| `family`                    | TEXT |          | 科（ナス科・ウリ科）。**R17 連作障害チェックの判定キー** |
| `default_unit`              | TEXT |          | 収穫の既定単位（個/g/束/株）                             |
| `created_at` / `updated_at` | TEXT | NOT NULL | ISO 8601                                                 |

データ投入は WBS 3.1（30 作物）。本書ではテーブルのみ定義する。

### 3.2 crop_calendars（栽培暦）

| 列                          | 型      | 制約                 | 説明                                                    |
| --------------------------- | ------- | -------------------- | ------------------------------------------------------- |
| `id`                        | TEXT    | PK                   |                                                         |
| `crop_id`                   | TEXT    | NOT NULL, FK → crops |                                                         |
| `region`                    | TEXT    | NOT NULL             | `cold` / `temperate` / `warm`（寒冷地/中間地/暖地）     |
| `kind`                      | TEXT    | NOT NULL             | `sow`（種まき）/ `plant`（植え付け）/ `harvest`（収穫） |
| `start_month` / `end_month` | INTEGER | NOT NULL             | 1〜12。年またぎは `start > end` で表す                  |

UNIQUE(`crop_id`, `region`, `kind`)。

### 3.3 crop_guides（作物ガイド）

| 列                     | 型      | 説明                                                        |
| ---------------------- | ------- | ----------------------------------------------------------- |
| `crop_id`              | TEXT    | PK, FK → crops                                              |
| `spacing_cm`           | INTEGER | 株間                                                        |
| `sunlight`             | TEXT    | `full` / `partial` / `shade`                                |
| `watering_note`        | TEXT    | 水やり頻度の説明                                            |
| `fertilize_after_days` | INTEGER | 植え付けから追肥までの日数。**R10「次の作業」の判定に使う** |
| `harvest_after_days`   | INTEGER | 植え付けから収穫目安までの日数。同上                        |
| `common_pests`         | TEXT    | よくある病害虫（JSON 配列）                                 |
| `tips`                 | TEXT    | よくある失敗とコツ                                          |

### 3.4 places（場所）

| 列            | 型      | 制約     | 説明                                 |
| ------------- | ------- | -------- | ------------------------------------ |
| `id`          | TEXT    | PK       |                                      |
| `name`        | TEXT    | NOT NULL | 「南の畝」「ベランダ プランター A」  |
| `kind`        | TEXT    |          | `planter` / `row` / `plot` / `other` |
| `note`        | TEXT    |          |                                      |
| `sort_order`  | INTEGER |          | 表示順                               |

### 3.5 plantings（栽培）

R01 の中核。だいどこの `recipes` に相当するが、版管理は持たない。

| 列                          | 型   | 制約                    | 説明                                                                               |
| --------------------------- | ---- | ----------------------- | ---------------------------------------------------------------------------------- |
| `id`                        | TEXT | PK                      |                                                                                    |
| `crop_id`                   | TEXT | FK → crops, **NULL 可** | マスターにない作物は NULL                                                          |
| `crop_name`                 | TEXT | NOT NULL                | 表示名。マスター参照時もコピーを持つ（マスター更新で過去の記録が変わらないように） |
| `variety`                   | TEXT |                         | 品種（アイコ）                                                                     |
| `place_id`                  | TEXT | FK → places             |                                                                                    |
| `planted_on`                | TEXT | NOT NULL                | 植え付け日（ISO 8601）                                                             |
| `planted_as`                | TEXT | NOT NULL                | `seed`（種）/ `seedling`（苗）                                                     |
| `cover_photo_id`            | TEXT | FK → photos             | 一覧のサムネイル                                                                   |
| `note`                      | TEXT |                         |                                                                                    |
| `ended_at`                  | TEXT |                         | 栽培終了（収穫完了・枯死）。NULL = 栽培中                                          |
| `ended_reason`              | TEXT |                         | `harvested` / `died` / `other`                                                     |
| `created_at` / `updated_at` | TEXT | NOT NULL                |                                                                                    |

INDEX(`place_id`), INDEX(`ended_at`), INDEX(`crop_id`)。

**`crop_name` を非正規化して持つ理由**: 作物マスターは WBS 3.1 以降も更新され続ける。参照だけにすると、マスターの名称変更が過去の栽培記録の表示を書き換えてしまう。

### 3.6 care_logs（作業ログ）

R04。だいどこの `cooking_logs` の構造をほぼそのまま使う。

| 列                          | 型   | 制約                     | 説明                                                              |
| --------------------------- | ---- | ------------------------ | ----------------------------------------------------------------- |
| `id`                        | TEXT | PK                       |                                                                   |
| `planting_id`               | TEXT | NOT NULL, FK → plantings |                                                                   |
| `kind`                      | TEXT | NOT NULL                 | `water` / `fertilize` / `transplant` / `prune` / `pest` / `other` |
| `logged_at`                 | TEXT | NOT NULL                 | 記録日時。既定は現在時刻                                          |
| `note`                      | TEXT |                          |                                                                   |
| `created_at` / `updated_at` | TEXT | NOT NULL                 |                                                                   |

INDEX(`planting_id`, `logged_at`), INDEX(`logged_at`)。

**収穫は含めない**（`harvests` へ分離）。タイムライン（R05）は `care_logs` と `harvests` を UNION して表示する。

### 3.7 harvests（収穫記録）

R06。数量・単位を持ち、R07 アルバムと R18 統計の対象。

| 列                          | 型   | 制約                     | 説明                                                                |
| --------------------------- | ---- | ------------------------ | ------------------------------------------------------------------- |
| `id`                        | TEXT | PK                       |                                                                     |
| `planting_id`               | TEXT | NOT NULL, FK → plantings |                                                                     |
| `harvested_at`              | TEXT | NOT NULL                 |                                                                     |
| `quantity`                  | REAL |                          | **任意入力**（R06 の受け入れ基準）                                  |
| `unit`                      | TEXT |                          | `piece` / `g` / `kg` / `bunch` / `plant`。既定は crops.default_unit |
| `note`                      | TEXT |                          |                                                                     |
| `created_at` / `updated_at` | TEXT | NOT NULL                 |                                                                     |

INDEX(`planting_id`, `harvested_at`), INDEX(`harvested_at`)。

### 3.8 photos（写真）

だいどこの `cooking_photos` を一般化する。作業ログ・収穫・栽培のいずれにも付く。

| 列                 | 型      | 制約     | 説明                                |
| ------------------ | ------- | -------- | ----------------------------------- |
| `id`               | TEXT    | PK       |                                     |
| `owner_type`       | TEXT    | NOT NULL | `care_log` / `harvest` / `planting` |
| `owner_id`         | TEXT    | NOT NULL |                                     |
| `local_path`       | TEXT    | NOT NULL |                                     |
| `width` / `height` | INTEGER |          |                                     |
| `sort_order`       | INTEGER | NOT NULL | 1 レコードあたり最大 6 枚（R04）    |
| `created_at`       | TEXT    | NOT NULL |                                     |

INDEX(`owner_type`, `owner_id`)。

**ポリモーフィック参照にした理由**: 作業ログ・収穫・栽培それぞれに写真テーブルを分けると、ギャラリー（R05/R07）が 3 テーブルの UNION になる。写真は「撮って並べる」用途が中心で、参照元の型に応じた列の差もないため 1 テーブルにまとめる。FK 制約は張れないので、削除時のカスケードはアプリ側で行う。

### 3.11 garden_shopping_items（買い物リスト）

R12 / WBS 2.7。**だいどこの `shopping_items` とは別テーブルにした。**
同じ表に載せると、タブから外しただけで残っている食材の買い物リストと混ざり、
菜園の買い物メモに「牛乳」が並ぶ。

| 列                | 型      | 制約                        | 説明                                         |
| ----------------- | ------- | --------------------------- | -------------------------------------------- |
| `id`              | TEXT    | PK                          |                                              |
| `family_id`       | TEXT    | NOT NULL FK → families      |                                              |
| `name`            | TEXT    | NOT NULL                    |                                              |
| `name_normalized` | TEXT    | NOT NULL                    | 重複追加の判定に使う（全角・カナ違いを畳む） |
| `amount`          | TEXT    |                             | 「2袋」「5m」など自由入力                    |
| `checked`         | INTEGER | NOT NULL DEFAULT 0          |                                              |
| `source`          | TEXT    | NOT NULL DEFAULT `'manual'` | `manual` / `low`（残りわずかから一括追加）   |
| `material_id`     | TEXT    | FK → materials              | 買ったときに在庫へ足し戻す先                 |
| `checked_at`      | TEXT    |                             | **最初に**チェックした時刻。外しても消さない |

`checked_at` を「最初の 1 回」の目印にしているのは、チェックを付け外しするたびに
在庫が増えると、レジ前の押し間違いで在庫が壊れるため。足す量は量の記述に
かかわらず 1 とする（単位が kg の資材に「2袋」を足すような取り違えを避ける）。

### 3.12 planting_tags / tags

`tags` はだいどこのものをそのまま使う。中間テーブルのみ `planting_tags`（`planting_id`, `tag_id`）として新設。

### 3.13 温存するテーブル

`users` / `families` / `family_members` は R19（v2.0 グループ共有）で「だいどこの families 構造を流用」と要件に明記があるため残す。

だいどこの `shopping_items` / `pantry_items` は**さいえん手帳では使わない**
（買い物リストは `garden_shopping_items`、在庫は `materials`）。画面が残っている
あいだはバックアップ対象に含めるが、削除は WBS 2.x の派生先が確定してから。

## 4. FTS5（全文検索）

R03 の検索要件（作物名・タグ・場所での絞り込み）に対応する。だいどこの `recipe_fts` と同じ方式。

```sql
CREATE VIRTUAL TABLE planting_fts USING fts5(
  planting_id UNINDEXED,
  crop_name,
  crop_name_reading,
  variety,
  tag_names
);
```

`fts.service.ts` の正規化（カタカナ → ひらがな、小文字化）をそのまま流用する。インデックス更新は栽培の作成・更新・削除時と、タグ付け替え時。
