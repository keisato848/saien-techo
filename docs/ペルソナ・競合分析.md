# さいえん手帳 — ペルソナ・競合分析

> 作成: 2026-07-28
> 位置づけ: docs/要件定義.md の根拠資料。競合体験の取り込み方針(§4)が要件 R25〜R31 の出典。

---

## 1. ペルソナ

### A. 週末菜園の会社員(主ターゲット)

- 40 代・会社員。市民農園または庭の一角で夏野菜 5〜8 品目、経験 2〜3 年
- 平日は仕事。畑に行けるのは週末だけ
- **課題:** 「先週追肥したっけ?」「去年トマトいつ植えたっけ?」を毎年繰り返す。現在の道具はスマホの写真フォルダと記憶
- **刺さる機能:** 「次の作業」アドバイス(R10)・リマインダー(R11)=週末の限られた時間で何をすべきか即断。「去年の今ごろ」(R27)

### B. ベランダ菜園の初心者

- 30 代。プランターでミニトマト・バジル・葉物。1 年目
- **課題:** 「次に何をすればいいか分からない」「葉が黄色いけど水のやりすぎ?」で検索を繰り返し、不安のまま枯らして辞めるのが典型パターン
- **刺さる機能:** 作物ガイド(R09)・今月の菜園仕事(R08)・AI 相談(R15)=検索の代わりに「自分の株」に紐づいた答え

### C. 定年後の本格菜園(副次ターゲット)

- 60 代。広い畑で多品目。管理は紙のノート派が多い
- 連作チェック(R17)・収穫アルバム(R07)は刺さり得るが、アプリ継続のハードルが高く、v1 で獲得コストをかけて狙う層ではない

## 2. 利用が成立する因果(仮説)

「①入れる理由 → ②開き続ける理由 → ③やめない理由」に機能を対応させる。

1. **獲得:** ペルソナ B の悩み検索(「トマト 葉 黄色」)に応える AI 診断・作物ガイドが入口。AI 診断の需要は PictureThis 等の成功が実証済み
2. **再訪:** 記録アプリの最大の死因は「開く理由がなくなる」こと。pull ではなく **push(リマインダー・次の作業通知)が再訪を作る**
3. **継続:** 収穫アルバムが達成感を作り、記録が翌シーズンに価値を持つ(ストック型)
4. 記録摩擦を 1〜3 タップ+写真に抑える型は、だいどこの「作った!」で設計検証済み

**最大のリスク仮説:** 「記録は 3 週間で飽きる」(②が機能しない)。検証は v0.5 段階で自分の菜園での 1 シーズン利用+少人数β。崩れたら機能追加より通知設計の作り直しを優先する。

**最大の競合は「何も使わない」(記憶+写真フォルダ)。** 移行動機は「去年を忘れて失敗した瞬間」に生まれるため、訴求は「記録しよう」ではなく「去年いつ植えたか、思い出せますか」型とする。

## 5. ポジショニング結論

差別化は単機能ではなく**「写真記録 × 自分の株に紐づくアドバイス × 非 SNS・オフライン」の組み合わせ**。単機能ごとには先行者がいるが、この組み合わせを日本の家庭菜園向けに揃えたものは現状見当たらない(2026-07 時点の調査)。

### 6.4 戦い方の変更 — 写真ベースへ(2026-08-18 決定)

**§5 の「組み合わせで差別化」は維持しつつ、突き方を「写真を入力にする」へ寄せる。**

**競合の写真は「見せるため」、さいえん手帳の写真は「記録になるため」。**
GreenSnap も菜園ナビも SNS なので、写真の役目は他人に見られること。写真を
**私的な構造化データ**に変えることは、注目とコミュニティで成り立つ事業に寄与しない。

> **「構造的に真似できない」とは書かない。** GreenSnap は既に植物名判定を持っており、
> 収穫物の判定は技術的に地続きで 3 か月あれば作れる。正しくは
> **「彼らの事業モデルでは優先度が上がらない」** — 観葉植物に収穫という概念が無く、
> SNS の収益は閲覧時間から来るので「記録を速く終わらせる」機能は逆行する。
> **堀は技術ではなく関心の向きにある。** 本気で来たら防げない前提で進める。

そしてこの領域だけ、写真が本当に最速の入力になる。土で汚れた手・しゃがんだ姿勢・片手・
日差しの反射・手袋。この条件下で**打つのは敵対的、選ぶのは平凡、撮るのは自然**。
料理アプリやメモアプリでは成り立たない前提が、庭では成り立つ。

計画は #143(体験)と #144(広告・枠・コスト)。**SNS は作らない** — 収穫カードの
書き出し(4.10)で「見せたい」を満たし、共有先は OS のシェアシート。
ここを曖昧にすると競合の土俵で規模負けする。

#### 6.5.1 野菜栽培図鑑 — 「栽培暦を持つ競合は無い」は誤り

| 項目           | 実態                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| アプリ ID      | `jp.ne.biglobe.khf.yuu7412369.VegetableDictionary`                                                        |
| 収録           | **約 80 種**(穀物含む)                                                                                    |
| 持っている情報 | 植え付け月・収穫月・栽培期間・科名・発芽適温・コンパニオンプランツ・**輪作年限**                          |
| 地域区分       | **「冷涼地」「一般(温暖)地」「暖地」の 3 区分**(初期値 = 一般(温暖)地)                                    |
| 価格・規模     | 無料。Android インストール 5,000〜・評価 3.9★。iOS 4.3★・レビュー 388 件、アプリ内課金 ¥150/月・¥1,200/年 |
| 最終更新       | **2026-08-26(v1.8.0)で「栽培記録機能」を追加**し、カレンダーメモを統合                                    |

**効いているのは最後の行。** 図鑑側から記録へ寄ってきている =
「暦を持つ図鑑」と「記録アプリ」の距離が縮んでいる。さいえん手帳は逆向き
(記録から暦へ)に同じ点を目指しているので、**正面の競合として扱う**。

**それでも取っていない差**: 図鑑の情報は**静的**で、

**ここは差にならない**ことを認めておく。

#### 6.5.2 菜園ナビ — 争っているのはアプリではなく「ブラウザで開く習慣」

§3 は菜園ナビを「機能的に最も近い」と書いたが、**中身を開いて確認したら前提が違った**。

- **作物ガイド「栽培教本」は 63 品目**(一覧を開いて全品目を数えた)。
  個別ページを 2 本開くと、**「畑の準備 → 植付け → 追肥 → 収穫」の散文 5 ステップのみ**で、
  **栽培暦なし・地域区分なし・出典なし**
- **App Store「菜園ナビ記録ツール」は説明文自身が「作物登録やコメント確認は本体サイトで行う」と明記**。
  **最終更新 2020-04-21(v2.0)**、3.7★・レビュー 12 件

→ **菜園ナビの本体は Web サイトで、アプリは記録の付属品**。
つまり**争っているのは「ブラウザで菜園ナビを開く習慣」であって、アプリ同士の機能比較ではない。**
§6.1 の「会員 32,000 人」も Web の会員数であって、アプリの利用者数ではない。
比較表(§6.2)に菜園ナビのアプリを並べていないのは、この理由で正しい。

#### 6.5.3 GreenSnap「2,400 種」を比較から外した

理由は §4 の表の直後に書いた。要約すると、
**対象(花・観葉植物中心)も情報の種類(水やり・日の当て方)も選定基準(投稿数)も違い、
野菜の栽培暦の品目数と並べられる数字ではない**ため。
削除であって「GreenSnap が弱い」という主張ではない。

#### 6.5.4 「今月なにをすべきか」を言うアプリは、やはり無い

野菜栽培図鑑を足しても、さらに §6.2 の 5 つの外にあるべじログ・Farm Reco を数えても、
§6.2 の中心の主張は崩れない。**「暦を持っていない」か「暦は持つが自分の株と突き合わせない」の
どちらか**に全部落ちる。

| アプリ               | 持っているもの                         | 「今月なにをすべきか」を言わない理由 |
| -------------------- | -------------------------------------- | ------------------------------------ |
| べじログ             | 経過日数の表示                         | 暦を持たない                         |
| Farm Reco / Plantoto | **自分で登録した予定**の通知           | 何をすべきかは利用者が決めて入れる   |
| 野菜栽培図鑑         | 栽培期間・植え付け月・収穫月(**静的**) | 自分の株の日付と突き合わせない       |
| GreenSnap / Greenery | 観葉植物のケア                         | 野菜の作型を持たない                 |

**海外には有る**(From Seed to Spoon・Seedtime)。「誰も思いつかない機能」ではなく
**「日本の作型データを整える手間を誰も払っていない」**という空白だと理解する。
だからこの空白は、こちらが品目のデータを積むほど広がるのではなく、
**誰かが同じ手間を払った時点で消える**。堀はデータを整える手間の大きさにしかない。
