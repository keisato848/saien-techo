## 5. AAB ビルドと提出

```powershell
# 1) 署名と広告の env を通す（値はチャット・ログに出さない）
$creds = Get-Content "C:\secure\saien-upload-credentials.properties" | Where-Object { $_ -match '=' }
foreach ($line in $creds) { $k, $v = $line -split '=', 2; Set-Item -Path "env:$k" -Value $v }
$env:EXPO_PUBLIC_ADMOB_ENABLED = "true"
$env:EXPO_PUBLIC_ADMOB_APP_OPEN_UNIT_ID = "ca-app-pub-2633806931583277/3771122951"
$env:EXPO_PUBLIC_ADMOB_REWARDED_UNIT_ID = "ca-app-pub-2633806931583277/3132828705"
$env:EXPO_PUBLIC_ADMOB_BANNER_UNIT_ID = "ca-app-pub-2633806931583277/6932472912"

# 2) ビルド（生 gradlew は禁止 — フックが止める。app.json 変更時は --prebuild）
node scripts/agent/build-android.mjs --bundle

# 3) 提出（リリースノートは listing-ja.md の「## リリースノート」節）
node scripts/release/submit-play-release.mjs --dry-run
node scripts/release/submit-play-release.mjs            # production へ
```

- **新規（未公開）アプリは draft リリースしか作れない**（スクリプトの既定）。AAB を載せたら
  Console の「公開の概要」→「変更を審査に送信」で申告一式と一緒に審査へ出す
- 公開後のアップデートは `--completed` を付ける（commit 即審査キュー）

- `bundleRelease` は SAIEN*UPLOAD*\* 未設定だと**意図的に失敗**する（debug 署名の AAB を
  Play へ上げない安全弁。build.gradle 末尾のゲート）
- 署名レール（signingConfigs.release + bundleRelease ゲート）は config plugin
  `plugins/withSaienUploadSigning.js` が prebuild のたびに自動注入する（android/ は
  gitignore のため手パッチは残らない — プラグインが単一ソース）
- versionCode は初回 1。**更新のたびに app.json の android.versionCode を上げる**

## 6. 提出後

- 新規アプリの初回審査は数日〜1 週間かかることがある。状態は Console の「公開の概要」
- 公開後にやること: AdMob のアプリを Play 掲載とリンク（承認状況「要審査」の解消）
- **app-ads.txt は任意（推奨）だが、現状は設置できない。** 設置先は「Play 掲載の
  ウェブサイトのドメイン直下」で、さいえん手帳は連絡先にメールしか設定していない。
  やるなら先に掲載情報へウェブサイト URL を足す（アカウント種別とは無関係）
