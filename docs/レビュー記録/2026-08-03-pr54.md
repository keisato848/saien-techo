## 指摘

### 1. レシート読み込みをスクショからも OCR できるようにできないか

- **状態**: done
- **重大度**: 中
- **指摘**: 園芸用品はネットで買うことも多い。なのでスクショからも OCR できるといいと思ったが、機能変更は可能か？
- **調査**: 実装を確認したところ、**変更は不要だった**。`apps/mobile/app/(tabs)/receipt.tsx:110,114` が既に `handlePick('camera')` と `handlePick('gallery')` の 2 系統を持ち、`photo-capture.service.ts` の `PhotoCaptureSource` が `'camera' | 'gallery'` を定義している。gallery は端末の写真ライブラリを開くため、スクリーンショットも対象に含まれる。OCR 側も `client-ocr.provider.ts` の `recognizeImage(imageUri)` が画像 URI を受け取るだけで、撮影経路を問わない。
  ただし**別の問題がある**。`apps/mobile/src/utils/receiptParser.ts` は紙のレシート前提のヒューリスティックで、`合計` `小計` `税` `内税` `外税` `標準税率` を含む行を除外し、行末の `¥1,280` / `128円` / `*128` を価格として拾う（`TRAILING_PRICE` 正規表現）。EC の注文確認画面は商品名が折り返し、価格が別行にあり、送料・ポイント行が混ざるなど書式が違うため、**OCR は通るがパースが合わない**可能性が高い。
- **判断**: 機能変更としては**対応不要**（既に実現できている）。ただしパーサが EC 画面に対応していない点は別要件として登録する。R31 菜園家計簿（資材購入額の記録）の範囲で、パーサを拡張するか AI（R14/R15 の Gemini 基盤）に構造化させるかを着手時に判断する。紙レシート用の行ヒューリスティックを EC 向けに条件分岐で伸ばすより AI に投げた方が筋が良いと考えるが、無料枠の消費とのトレードオフがある。
- **対応**: 要件定義 R31 に補足を追記

### 2. レビュー記録をリポジトリ全体で統一的に管理するハーネスにしてほしい

- **状態**: done
- **重大度**: 高
- **指摘**: レビュー記録はリポジトリ全体で統一的に管理するようなハーネスに変更してほしい。
- **調査**: 現状、レビュー結果の残り方が 3 通りに分裂していた。(1) harness-reviewer の監査レポートは会話にしか存在しない、(2) PR のレビューコメントは GitHub 側にあってリポジトリから追えない、(3) 会話で受けた指摘はどこにも残らない。このセッションだけでも「Gotchas は書かない」「OCR は残す」「AVD は作り直す」など**見送り・保留の判断**が複数あり、根拠が会話に埋もれると同じ議論を繰り返す。
- **判断**: 対応する。`docs/レビュー記録/` に 1 レビュー 1 ファイルで残し、各指摘に状態・重大度・調査・判断・対応を必ず持たせる。「見送る」も状態 `wontfix` として理由つきで残し、ファイルからは消さない。索引と未対応件数は機械生成にして手で数えない。
- **対応**: 本 PR（`review-log` スキル + `scripts/agent/review-log.mjs` + pre-commit 配線）
