## 指摘

### 1. 列名が変わると「訪問者 0」を静かに出す

- **状態**: done
- **重大度**: 高
- **指摘**: `summarizeStorePerformance` は想定した列が無いとき `visitors: 0` で続行するため、CSV の書式が変わると「誰も来ていない」と誤認させる。
- **調査**: **当たり。** 該当箇所で 0 を返しており、描画側も判定していなかった。前日に ASC 側の同じ問題（`summarizeBySource`）は直していたのに、Play 側は同じ形のまま残っていた。
- **判断**: 採用。`visitors` を `null` にし、`unreadable` と実際の列名を返す。描画側は読めなかった月を表から外し、理由と実際の列名を出す。
- **対応**: 列名を壊した入力で、表に 0 が並ばず理由と列名が出ることを確認済み

### 2. サブタイトルの更新が複数の appInfo を書き換える

- **状態**: done
- **重大度**: 中
- **指摘**: 更新に成功しても `break` せず次の appInfo を試すため、別の状態のものまで上書きする。
- **調査**: **当たり。** 成功後も `continue` していた。公開中のものは失敗して握りつぶされるが、編集可能なものが複数あれば全部書き換わる。
- **判断**: 採用。1 つ更新できたら抜ける。
- **対応**: `break` を追加

### 3. 未生成の日を集計期間の終わりにしている

- **状態**: done
- **重大度**: 低
- **指摘**: 「未生成の日を期間に含めない」とコメントしながら、`to` には常に要求した最終日が入る。
- **調査**: **当たり。** コメントと実装が食い違っていた。実際に集計できた日を記録していなかった。
- **判断**: 採用。集計できた日を貯め、その最終日を `to` にする。要求した範囲は `requestedTo` に残す。
- **対応**: 同上

### 4. 失敗経路のテストがタイマーを進めていない

- **状態**: done
- **重大度**: 中
- **指摘**: 成功時の遷移が 900ms の `setTimeout` なので、進めずに assert すると遷移を止められていなくても通る。
- **調査**: **当たり。** 前日に自分で足したテストで、同じ「歯が無い」問題を繰り返していた。
- **判断**: 採用。偽タイマーで 2 秒進めてから確かめる。
- **対応**: `jest.advanceTimersByTime(2000)` を追加

### 5. Play の文字数の数え方

- **状態**: done
- **重大度**: 低
- **指摘**（推測と明記されていた）: Play は UTF-16 単位で数えるかもしれず、符号位置で数えると上限検査をすり抜ける。
- **調査**: **未確認。** Play がどちらで数えるかは一次情報を取れていない。現在の掲載文にサロゲートペアは無いので今は影響しない。ただし検査が甘い側に倒れていると、送ってから API に弾かれる。
- **判断**: 採用（安全側）。**どちらが正か決めずに、両方の数え方の大きい方**で検査する。
- **対応**: `Math.max([...s].length, s.length)` で検査

### 6. ブラウザのプロファイルに Google アカウント全体のセッションが入る

- **状態**: open
- **重大度**: 高
- **指摘**: Play Console 取得用のプロファイルには開発者アカウント全体のセッションが含まれ、同じ端末の他のプロセスから Gmail や Drive にも届く。閲覧専用の別アカウントを用意すべき。
- **調査**: **当たり（設計上のリスク）。** 前日の別レビューでも同じ指摘があった。コードの不具合ではなく運用の設計。Windows の Chrome cookie は同一 Windows ユーザーに紐づくので機外への単純コピーでは復号できないが、**同じユーザーで動く任意のプロセスからは読める**。
- **判断**: **利用者の判断が要るため保留。** 統計の閲覧だけができる別の Google アカウントを Play Console に招待し、そのアカウントでログインする案が有力。ここで勝手にアカウントを増やさない。
- **対応**: 未対応。リリース後に判断する

### 7. ベンダー番号がエラー詳細から漏れる

- **状態**: wontfix
- **重大度**: 低
- **指摘**（推測と明記されていた）: Apple のエラー詳細にベンダー番号が含まれると、summary.md やログに出る。
- **調査**: **外れ。** 2026-09-17 に実際に誤った番号と未指定の両方を試しており、Apple の応答は「Invalid vendor number specified. Try again.」と「The parameter 'filter[vendorNumber]' is required but was not provided」で、**どちらも番号そのものを返していない**。
- **判断**: 見送る。実測で否定された。将来 Apple が本文を変えたら再検討する。
- **対応**: なし
