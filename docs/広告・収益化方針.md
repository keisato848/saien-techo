# 広告・収益化方針（判断③・2026-08-06 確定）

> 関連: docs/WBS.md 3.7（AdMob 組み込み）/ 4.3（freemium・RevenueCat）/ 5.4（アフィリエイト）、
> docs/要件定義.md §8。判断③は「v1.0 から広告あり」で確定。

## フェーズ別の収益化

| フェーズ      | 収益化                                                      | 実装                                                                                         |
| ------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| v1.0（10 月） | **起動広告（頻度制限付き）**                                | 3.7: AdMob 実 ID 投入・ユニット発行・UMP 同意導線の復活。課金なし                            |
| v1.5（11 月） | freemium: AI 無料枠＋**リワード広告**＋BYOK＋プレミアム課金 | 4.1/4.2 と同時。RevenueCat 有効化                                                            |
| v1.6（1 月）  | 文脈アフィリエイト                                          | **4.11**(5.4 から繰り上げ): 作物ガイド「この時期に買うもの」・買い物リストから楽天/Amazon へ |

- バナー常設はやらない。滞在の短い記録アプリでは単価が低い割に体験を削る
- SDK の扱い: AdMob/UMP・RevenueCat とも**同梱のまま**。RevenueCat は v1.5 まで未初期化
  （entitlement.service は API キー未設定なら stub 経路）

## 個人情報の扱い（2026-08-06 調査）

### 利用者の個人情報

- AdMob・アフィリエイトとも、**利用者の個人情報が運営者や広告主に開示されることはない**
  （広告 ID・クッキーによる計測。アフィリエイトのレポートは商品単位の匿名集計）
- ただし「収集」はされるため、プライバシーポリシー記載と Play データセーフティ申告が必要（3.8）。
  広告 SDK 分の申告を含める

### 運営者（開発者）の個人情報 — Google Play の表示要件

| アカウント状態                                            | ストアに公開されるもの |
| --------------------------------------------------------- | ---------------------- |
| 個人・無料・課金なし                                      | メールアドレスのみ     |
| 個人・**有料/アプリ内課金あり**（トレーダー扱い・EU DSA） | **氏名（本名）＋住所** |

- **広告のみの v1.0 では本名・住所は公開されない**
- **v1.5 でプレミアム課金を入れる時点で公開対象になる** → 4.3 着手時の判断ポイント。
  回避の定番はバーチャルオフィス住所（組織アカウント化は法人＋D-U-N-S が必要）
- 特商法: Play では開発者が販売者になるため、課金開始時に通信販売表記の整理が必要
  （個人は「請求があったら遅滞なく開示」方式の余地あり — 4.3 で確認）

### 法規制・規約の注意（5.4 アフィリエイト着手時に必ず確認）

1. **ステマ規制（景表法・2023-10〜）**: アフィリエイトリンクには「広告」「PR」の明示が必須
2. **Amazon アソシエイト**: 「アソシエイトとして収入を得ています」表記が必須（名前はアプリ名で可）。
   **モバイルアプリ内での利用は Web 媒体と規約が異なり、要承認の可能性が高い** — 一次規約で確定させること
3. **楽天アフィリエイト**: 同じく**アプリを掲載媒体にできるかを一次規約で確認**してから着手

## アフィリエイトのレコメンド設計（4.11・2026-08-07 追記）

「AI にレコメンドさせる」は 3 段で考える。**既定はルールベース（コスト 0）**で、
AI は質を上げたい所にだけ足す。

| 段階                           | 方式                                                                                                                                                         | 実行時コスト                                                                                                                                               | 時期                              |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 1. ルールベース                | マスターに「関連資材」を持たせる（例: ダイコンまきどき → 種・防虫ネット / トマト定植 → 支柱・苗 / アブラムシ → 薬剤）。作物 × 月 × 地域で決まるので LLM 不要 | **0 円**                                                                                                                                                   | 4.11 の既定                       |
| 2. ビルド時 AI 生成            | 推薦文・資材マッピングを開発時に Claude で生成してマスターに焼き込む。実行時は静的データ                                                                     | 開発時のみ数百円未満（一度きり）                                                                                                                           | 4.11 に含めてよい                 |
| 3. 実行時 AI（パーソナライズ） | 利用者の栽培・作業ログ・地域を踏まえた提案。v1.5 の AI 基盤（4.2 のサーバー/BYOK/無料枠）に相乗り                                                            | 約 0.3〜0.5 円/回（Haiku 級: 入力 1.5k+出力 0.3k トークン想定）。月 4,000 回でも約 2,000 円/月。無料枠・BYOK・プレミアムの管理下に置けるので原価は制御可能 | v2.0 で検討（プレミアム特典候補） |

- 「結構コストがかかるか」への答え: **実行時 AI でも 1 回 1 円未満**。ただし推薦の大半は
  作物 × 時期で決まる静的な内容なので、段階 1+2 でほぼゼロ円のまま同等の体験が作れる
- 実行時 AI を使う場合も、**商品そのものを AI に選ばせない**（存在しない商品・リンク切れ・
  規約リスク）。AI は「資材カテゴリと理由の文言」まで。商品リンクは検索リンクか手動キュレーション
- 前提条件（着手前に確定）: 楽天アフィリエイト・Amazon アソシエイトの**アプリ内掲載可否を
  一次規約で確認**。不可なら ASP（アプリ媒体可のもの）や Web ページ経由に切り替える。
  掲載時は景表法のステマ規制に基づく「広告/PR」表記を必ず付ける
