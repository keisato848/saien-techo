# 検討: 作物マスターを 30 品目から 100 品目へ（2026-09-05）

> 発端: 「小松菜は収穫まで何日と表示されたが、ルッコラと空芯菜は表示されなかった」。
> 原因は不具合ではなく、作物マスター（`apps/mobile/src/db/crop-master.ts`・v3）に
> 2 つとも載っていないため。ここから「100 品目くらい行きたい」となった。
> **実装はまだしていない。** 設計判断とデータの段取りを決めた記録。第 1 段の Issue は #180。
>
> 関連: R08（栽培暦）/ R09（作物ガイド）/ WBS 3.1（30 作物・判断②）/ WBS 4.12（旬への細分化）/
> docs/栽培暦の出典.md（出典と検証記録）

---

## 0. 結論（3 行）

- **100 品目は出せる。律速はコードではなくデータ。** 1 品目あたり出典の照合込みで 30〜60 分、
  70 品目で 35〜70 時間。コード側の改修は 1〜2 日
- **データを足す前に設計を 3 か所直す。** 「今月の菜園仕事」の件数上限・作物ガイド一覧の分類と検索・
  多年草（収穫日数が単一の数値で表せない）
- **3 段階で入れる。** 50 → 75 → 100。各段で `CROP_MASTER_VERSION` を上げる

## 1. いま何が起きているか

| 事実                                                                                     | 場所                                           |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------- |
| マスターは 30 品目（秋冬 12 + 春夏 18）                                                  | `crop-master.ts` `CROP_MASTER`                 |
| 「収穫まで N 日」はマスターの `harvestAfterDays` から計算。無ければ帯を描かない          | `growth-progress.service.ts:79-89`             |
| 出典は**全体で 1 リスト**（4 資料）。作物ごとの対応は持っていない                        | `crop-master.ts` `CROP_MASTER_REFERENCES`      |
| 寒冷地の実期の裏どりは JA 北海道の **13 品目だけ**。中間地・暖地は「定説の範囲」で未補正 | docs/栽培暦の出典.md                           |
| 別名表がマスターに**無い**作物を指している（トウガラシ・インゲン・サヤエンドウ）         | `crop-match.service.ts` `CROP_NAME_ALIASES`    |
| 「今月の菜園仕事」は該当作物名を読点でつないで**全部**出す。上限なし                     | `MonthlyWorkCard.tsx:59`                       |
| 作物ガイド一覧は科を添えた単純な一覧。検索・分類なし                                     | `app/(tabs)/crops/index.tsx`                   |
| DB の `crop_guides.harvest_after_days` は **nullable**。「次の作業」も null を素通しする | `schema.ts:143` / `next-action.service.ts:130` |

最後の行が効いていて、多年草を入れるのに DB 移行は要らない。マスターの型を緩めるだけでよい。

## 2. 決めたこと（2026-09-05）

| #   | 論点                                             | 決定                                                                                                                                                               |
| --- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ①   | 多年草（アスパラガス・ミョウガ・果樹）を入れるか | **入れる。** `harvestAfterDays: number \| null` にし、`perennial: true` を持たせて「翌年から」と出す                                                               |
| ②   | 出典を作物ごとに持つか                           | **持つ。** マスターに `sourceIds: string[]` を足し、`CROP_MASTER_REFERENCES` に `id` を付ける。DB 列は足さない（ガイド画面がコードのマスターを id で引けば足りる） |
| ③   | 公的資料で足りない分に種苗会社の公開表を使うか   | **公的を優先し、不足分だけ許す。** ハーブ・果樹は県指針に薄いので、農研機構・県の園芸試験場 → それでも無ければ種苗会社の公開表。出典として明記する                 |

### ①の理由

「植え付けから収穫まで何日」は一年草の枠組みで、多年草は「植えて翌年（果樹は 2〜3 年）から毎年採る」。
無理に日数を置くと進行帯が嘘になる。null なら進行帯は既に「目安なし」として経過日数だけを出す設計
（`growth-progress.service.ts` 冒頭のコメント）で、「次の作業」も null を提案対象から外す。
壊れるのはテスト `ガイドの日数は 追肥 < 収穫` だけで、null を除外すればよい。

### ②の理由

100 品目で全体 1 リストだと「この作物はどの資料か」が追えない。資料を差し替えたときの影響範囲も
分からなくなる。作物ガイド画面の脚注に「この作物の出典」を出せるようになる。

### ③の理由

docs/栽培暦の出典.md の方針「人手レビューの代わりに公的資料と突き合わせる」を崩さない。
ただし公的資料の作型表は主要野菜に偏っていて、ハーブ・果樹・地方野菜は載らないことが多い。

## 3. 設計変更（データより先に入れる）

### 3-1. マスターの型

```ts
export interface CropMaster {
  id: string;
  name: string;
  nameReading: string;
  family: string;
  /** 一覧の分類・検索の絞り込み。DB の crops.category にも持つ */
  category: CropCategory;
  defaultUnit: ...;
  /** 多年草。収穫日数を持たず、ガイドに「翌年から収穫」と出す */
  perennial?: true;
  /** CROP_MASTER_REFERENCES の id。1 つ以上 */
  sourceIds: string[];
  calendars: CropCalendarWindow[];
  guide: CropGuideMaster; // harvestAfterDays: number | null
}

export type CropCategory =
  | 'leaf'    // 葉菜
  | 'root'    // 根菜
  | 'fruit'   // 果菜
  | 'bean'    // 豆
  | 'tuber'   // いも
  | 'allium'  // ネギ類
  | 'herb'    // ハーブ
  | 'tree';   // 果樹・多年
```

- `category` は **`crops` テーブルに列を足す**（一覧・検索が DB から引くため）。移行 1 本と
  `syncCropMaster` の書き込み追加。既存のユーザー作成作物は null のまま
- `sourceIds` は DB に持たない（②）
- `CROP_MASTER_REFERENCES` の各要素に `id`（例: `maff-sehi`, `ja-hokkaido`）を付け、
  構造テストで「全作物の sourceIds が実在する id を指す」を強制する

### 3-2. 「今月の菜園仕事」の畳み込み

行ごとに **6 種まで**出し、残りは「ほか N 種」。タップで作物ガイドへ、**今月で絞った状態**で開く。
30 品目でも 5 月のまきどきは 10 種を超えているので、これは 100 品目の前から要る。

### 3-3. 作物ガイド一覧

分類（3-1 の `category`）でセクションを切り、上に検索欄（名前・読み・別名）。
「今月まける／植えられる／採れる」のフィルタチップを 1 つ持つと 3-2 の受け皿になる。

### 3-4. 小さいもの

- **id の命名**: 既存はローマ字（`crop-kyabetsu`）と英語（`crop-cucumber`）が混在。
  **既存は変えない**（`plantings.crop_id` に保存済み。変えると栽培が孤児になる）。
  新規は **和名のヘボン式ローマ字**で統一（`crop-rukkora` / `crop-kushinsai` / `crop-shishito`）
- **別名表の空振り解消**: トウガラシ・インゲン・サヤエンドウを第 1 段で入れる
- **テスト `30 作物そろっている`** は「第 N 段の目標数」に書き換える（下限で見る）
- **AI の写真登録**（1.3）は作物名で名寄せしているので、マスターが増えるほど当たる。
  追加作業は要らないが、別名表（店頭の呼び方）は品目と一緒に足す

## 5. 100 品目の候補と段階

既存 30 は変えない。新規 70 を 3 段に分ける。**段ごとに `CROP_MASTER_VERSION` を上げる。**

### 第 1 段: +20 → 50 品目（設計変更と同時）

穴として現れているものと、家庭菜園の頻出。多年草は 2 つだけ入れて型を通す。

| 分類   | 品目                                                               |
| ------ | ------------------------------------------------------------------ |
| 葉菜   | ルッコラ・空芯菜・チンゲンサイ・モロヘイヤ・サンチュ・カリフラワー |
| 根菜   | ラディッシュ・ショウガ                                             |
| 果菜   | トウガラシ（シシトウ含む）・パプリカ・スイカ                       |
| 豆     | インゲン・サヤエンドウ・ソラマメ・ラッカセイ                       |
| いも   | サトイモ                                                           |
| ネギ類 | 長ネギ・ニラ（多年）                                               |
| ハーブ | パセリ                                                             |
| 多年   | ミョウガ（多年）                                                   |

### 第 2 段: +25 → 75 品目

| 分類   | 品目                                                       |
| ------ | ---------------------------------------------------------- |
| 葉菜   | ケール・ターサイ・ノザワナ・タカナ・ミツバ・セロリ・エゴマ |
| 根菜   | ビーツ・ゴボウ・ナガイモ                                   |
| 果菜   | メロン・マクワウリ・トウガン                               |

### 第 3 段: +25 → 100 品目

| 分類   | 品目                                                                               |
| ------ | ---------------------------------------------------------------------------------- |
| 葉菜   | カラシナ・ワサビナ・スイスチャード・コールラビ・芽キャベツ・エンダイブ・セリ       |
| 果菜   | ヘチマ・ハヤトウリ・シカクマメ                                                     |
| ハーブ | カモミール・レモングラス・オレガノ・セージ・イタリアンパセリ・チャイブ・ラベンダー |
| 多年   | フキ・ルバーブ                                                                     |
| 果樹   | ブルーベリー・イチジク・ラズベリー・ユズ・レモン・ブドウ                           |

### 落としたもの

- 穀物・油糧（ソバ・ゴマ）: 家庭菜園の手帳の主語ではない
- 観賞用（ヒマワリ・ナスタチウム）: 「収穫」の枠に合わない
- 品種レベル（ミニトマト・ミニ白菜・九条ねぎ）: **別名表で親に寄せる**。マスターに増やさない

## 7. WBS 4.12（旬への細分化）との順番

4.12 を先にやると、新規 70 品目を最初から旬で書くことになり、旬の作型表が無い品目で詰まる。
**4.19（本件）を月単位で先に入れ、4.12 は「月までしか分からない品目は上旬〜下旬まるごと」を
許す形にする**。そうすれば 100 品目の書き直しは強制されない。
