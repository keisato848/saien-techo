> 作成: 2026-08-03（WBS 1.4）
> ステータス: v0.1 Alpha の 3 画面のみ確定。以降の画面は各 WBS 着手時に追記する
> 比較モック: `mockup/palette-compare.html`（ブラウザで直接開ける）

## 1. 配色

**若葉を既定とする**（2026-08-03 決定）。4 案をモックで見比べて選定した。

| 案       | 性格                                                          | 状態     |
| -------- | ------------------------------------------------------------- | -------- |
| **若葉** | 春の新芽の黄緑。彩度が高く軽い。「これから育つ」印象          | **既定** |
| 苗床     | セージ × 土色。紙の菜園手帳の延長。彩度が低く写真が主役になる | 選択可   |
| 深緑     | 青みの深い葉緑。輪郭が硬く、記録ツールとしての精度が出る      | 選択可   |
| 土       | 土の黒に葉の黄緑。夕方の屋外で見やすい暗色案                  | 選択可   |

4 案とも `apps/mobile/src/constants/theme.ts` の `PALETTES` に実装済みで、`ACTIVE_PALETTE`
を変えるだけで全画面が入れ替わる。実機で比較するときはビルド時に環境変数で指定する。

```bash
EXPO_PUBLIC_PALETTE=naedoko node scripts/agent/build-android.mjs --arch x86_64
```

### トークンの命名

意味的な名前（`accent` / `ink` / `surface` …）を新しい画面で使う。
`gold` / `paper` などのだいどこ由来のキーは**移行期間の別名**として残してあり、
recipes 系の画面が消えた時点（WBS 1.5 完了後）に削除する。

`harvest` はアクセントとは別系統の色。収穫は本アプリの中核（要件 §1 の 3 本柱）で、
作業ログと視覚的に区別する必要があるため、緑ではなく暖色を当てている。

`danger`（エラー・破壊的操作）は `harvest` とは別に持つ。同じ暖色で兼ねると
「削除」と「収穫」が同じ色になり、どちらも頻出する本アプリでは取り違えが起きる。

### フォント

**和文に webfont は積まない。** APK が膨らむうえ、和文はシステムフォントの方が読みやすい。
`Fonts.system` のみを持ち、ウェイトとサイズで階層を作る。

だいどこは `Cormorant Garamond` をワードマークに使っていたが、さいえん手帳では
装飾フォントを持たない方針とし、`Fonts.brand` は削除した。

## 1.5 シンボル(2026-08-04 決定)

「**畝と芽**」。畝から芽が生えている形。

正は `apps/mobile/assets/brand/mark.svg` で、アイコン・スプラッシュ・favicon は
`pnpm assets:brand` がそこから書き出す。PNG は生成物なので直接編集しない
(pre-commit の `--check` が SVG との食い違いを落とす)。

### 4 案から選んだ理由

| 案         | 内容                      | 判断                                             |
| ---------- | ------------------------- | ------------------------------------------------ |
| 綴じ葉     | 葉の主脈を手帳の綴じ穴に  | 手帳らしさは一番。見送り                         |
| 栞葉       | 葉の裾を栞の切り欠きに    | 輪郭が最も単純。見送り                           |
| **畝と芽** | 畝から芽が生えている      | **採用**。場所を持つアプリだと分かるのはこれだけ |
| 葉と実     | 記録(葉)と収穫(実)の 2 色 | 目を引くが単色で関係が弱る。見送り               |

### 形の決めごと

- **畝を最後に描いて茎の根元を覆う。** 芽を宙に浮かせると、畑ではなく観葉植物に見える
- **双葉は左右で大きさを変える。** 左右対称にすると図形記号に寄りすぎる
- **線は太い**(茎 9 / 畝 10 / 96 基準)。24px まで縮めても潰れないことを実測で確認した

畝を折って芽が抜ける形も描いたが、アイコンの大きさでは断片が寄り集まって
「K」のような抽象記号に見えたため不採用。**大きく描いた図が小さくすると別物に見える**のは
毎回起きるので、決める前に必ず 24/48px で見ること。

## 3. 画面構成

### タブ

| タブ   | 画面                                               | 要件                  |
| ------ | -------------------------------------------------- | --------------------- |
| ホーム | 今日の菜園（次の作業・今月の菜園仕事・最近の記録） | R05 / R08 / R10       |
| 栽培   | 栽培一覧 → 栽培詳細                                | R01 / R03 / R04 / R06 |
| 収穫   | 収穫アルバム                                       | R07                   |
| 設定   | 設定                                               | R13 ほか              |

タブは **ホーム / 栽培 / ＋ / 収穫 / 設定** の 5 つ。

**中央の「＋」はタブではなく「栽培を追加」への近道**にしている（WBS 1.5）。
だいどこの `add.tsx` はレシピの作成方法を選ぶシートだったが、さいえん手帳では
分岐が 1 つしかないため、シートを挟まず登録画面へ直行させる。

**登録・編集画面は栽培スタックの中に置く**（`app/(tabs)/plantings/new.tsx`）。
ルート直下に `app/plantings/` を作ると `/plantings` がそちらに解決され、
index を持たないため deep link が空画面になる（実機で踏んだ）。

**収穫を独立タブにした理由**: 要件 §1 で収穫は 3 本柱の 1 つに格上げされている。
栽培の中に畳むと「今日の採れたてを撮る」導線が 2 階層深くなり、R06 の
「最短 3 タップ」を満たせない。

## 4. 画面詳細（v0.1 Alpha）

### S01 ホーム — 今日の菜園

**予定 → 提案 → 自分の畑 → 季節 → 履歴**（並びは WBS 3.5 で確定）。

1. **今日のリマインダー** — 自分で設定した今日の予定を時刻順に（R11）— **WBS 3.5**
2. **つぎの作業**（アクセント面のカード）— 栽培ごとに植え付けからの経過日数と
   作物ガイドを突き合わせた提案。「記録する」で該当の記録画面へ、「あとで」で消す（R10）
   — **WBS 3.4**（作物暦 WBS 3.1 の後）
3. **育てているもの** — 育成中の栽培を横スクロールで。経過日数付き
4. **今月の菜園仕事** — 作物暦から今月まける種・植えられる苗（R08）— **WBS 3.2**
5. **さいきんの記録** — 作業ログを日付ごとに束ねて時系列（R05）

収穫は左のドットを暖色にして作業ログと区別する（WBS 2.1）。

**1 と 2 の順**: どちらも行動を促すが、自分で設定した予定の方が確度が高いので上。
ただし**アクセント面は「つぎの作業」に残す** — ホームで唯一のアクセント面という
取り決めを崩さないため、リマインダーは通常面にする。事実（予定）を淡く、
提案（行動）を強く、の対比で読ませる。

**カードが積み上がらない理由**: 1・2・4 は中身が無ければカードごと消える。
予定も提案も無い日はホームが「育てているもの＋記録」だけになる。

**リマインダーは時刻を過ぎても残す**: 朝 7 時の水やりを 18 時に確かめたいことの方が
多く、過ぎたら消える一覧では「やったか分からない」が残る。済みの判定は
リマインダー自身ではなく**その日の記録の有無**で行う（リマインダーは「鳴らした」
ことしか知らないため）。

**日付見出しを相対表記にした理由**（WBS 1.9）: 菜園では「何日前にやったか」が
知りたい情報。直近 1 週間は「今日 / きのう / N日前」、それ以降は日付にする。
束ね方は**端末のタイムゾーン**で決める（`toISOString()` の日付で束ねると
深夜の記録が前日に混ざる）。

**空状態**: 栽培も記録も無いときだけ「さいえん手帳へようこそ」を出す。
栽培はあるが記録が無い状態では、記録の付け方を文章で案内する
（空状態カードを重ねると画面が説明だらけになる）。

**ようこその下に「今月の菜園仕事」も出す**（WBS 3.5 で判断）。まだ何も植えて
いない人にとって「今月なにを植えられるか」は最も役に立つ情報で、すでに実装がある。
ここを空にすると、栽培を登録するまで何も分からない行き止まりになる。
「説明だらけにしない」方針とは矛盾しない — これは説明ではなく中身のある情報のため。

### S02 栽培一覧

- 「育成中 / 終了した栽培」の切り替え（R01 のアーカイブ、R03）
- 1 行に 作物名・品種・場所・**経過日数**。経過日数はアクセント色で右端に置く
- 検索は作物名・品種・タグ・場所（FTS5。`planting_fts`）— **WBS 1.7 で実装**

並び順は植え付け日の新しい順（WBS 1.5 で決定）。直近に植えたものほど
様子を見に行く頻度が高く、記録も付きやすいため。「次の作業が近い順」は
R10 のアドバイスエンジン（WBS 3.4）が入るまで根拠を持てない。

**経過日数の止め方**: 栽培終了後は終了日で止める。終了した株の「300 日経過」に
意味はなく、知りたいのは栽培期間のため。

### S03 栽培詳細

1. **「やった！」を記録** — 水やり / 追肥 / 剪定 / 防除 の 4 ボタン。
   タップで**即保存**し、トーストを出すだけにする。ここでシートを挟むと
   タップ数が増えて R04 の「1〜2 タップ」を満たせない。写真とメモは
   一覧から開いて後から足せる。植え替えは頻度が低いので
   「写真やメモを付けて記録」の側にだけ置く
2. **収穫** — その栽培の収穫写真をグリッド表示。合計を暖色のピルで（R06 / R07）
3. **作業ログ** — 時系列。写真はサムネイル 4 枚まで並べ、超過分は「+N」で畳む（R04）

#### 収穫を作業ログと分けている点

画面上は同じ「やったことの記録」に見えるが、保存先は `care_logs` と `harvests` で
分かれている（数量・単位を持ち R07 アルバムと R18 統計の対象になるため）。
クイック記録では 4 つの作業ボタンの下に「収穫した」を**暖色で**置き、
色だけで別物だと分かるようにしている。

#### 収穫の記録（R06 / WBS 2.1）

**写真が主役で、数量は任意。** フォームは上から 写真 → 収穫日 → とれた量 → メモ の順。
数量を上に置くと「数えないと記録できない」ように見えて、記録そのものが止まる。

**「収穫した」を押すとカメラが立ち上がる。** 収穫 → 撮影 → 記録 の 3 タップで終わる
（R06 の受け入れ基準）。ここにシートを挟むと 4 タップになって満たせない。
撮影を取り消してもフォームには留まるので、ギャラリーにも切り替えられる。

単位は作物マスターの既定値を選んだ状態で開く（トマトなら「個」）。
マスターに無い作物や、既定値が未知の値のときは未選択にする。

**合計は単位ごとに分ける。**「個」と「g」は足せないため、1 つの数にまとめない。
数量が未入力の収穫は合計に入らない（写真だけの記録があるため）。

**収穫ボタンを 5 つ目に混ぜた理由**: 収穫は作業ログとは別テーブル（`harvests`）だが、
ユーザーにとっては同じ「やったことの記録」。導線を分けると 3 タップに収まらない。

#### 「栽培終了」と「削除」を分けた理由（WBS 1.5）

だいどこの `deleteRecipe` は `status='archived'` の論理削除だったが、栽培では
アーカイブに相当するのが **栽培終了**（`ended_at`）で、これは「終了した栽培」から
参照できる正規の状態。削除まで論理削除にすると、終了一覧に削除済みが混ざる。

- **栽培を終了する** — 収穫完了 / 枯れた / その他 を選ぶ。記録は残る。取り消せる
- **削除する** — 確認ダイアログ付きの物理削除。作業ログ・収穫・写真・リマインダーも消す

削除の確認文には「記録を残したい場合は栽培を終了する」を明示して、
取り違えを文言で止めている。

### S05 場所の管理（設定 → 菜園 → 場所の管理）

プランター・畝・区画の CRUD。栽培フォームの場所ピッカーの元になる。

**並べ替えを持つ理由**: ピッカーの並びは「畑を歩く順」であってほしい。
名前順だと現実の配置と対応せず、登録のたびに目で探すことになる。
上下ボタンにしたのは、場所はたかだか十数件で、短い行のドラッグは誤操作が多いため。

**「使わない」（アーカイブ）と「削除」を分けた理由**: 場所を物理削除すると、
そこで育てた過去の栽培から場所名が失われて記録の価値が落ちる。
そのため既定はアーカイブで、**まだ 1 度も栽培に使われていない場所だけ**削除できる
（作り間違いの取り消し）。編集画面では使用中の場合に削除ボタンを出さず、
理由を文章で示す。

栽培フォームからも「場所を追加」で直接飛べる。苗を持ったまま登録している最中に
場所が未登録だと詰むため。

### S04 収穫アルバム（R07 / WBS 2.2）

収穫写真を月別のグリッドで並べる。作物で絞れる。

**写真 1 枚が 1 マス**（収穫 1 件ではない）。1 回の収穫で複数枚撮ったとき、
1 枚しか見えないとアルバムとして意味を成さない。

**写真の無い収穫もマスとして出す。** 写真だけを並べると、数量だけ記録した収穫が
一覧から消えてしまう。写真の代わりに暖色の籠アイコンを置く。

- **3 列**。2 列だと写真が大きすぎて 1 か月が縦に長くなり、4 列だと何か分からない
- 月見出しは**今年なら年を省く**。毎行に年が付くと月の違いが読み取りにくい
- 月の束ね方は端末のタイムゾーンで決める（`toISOString()` だと月初 0 時台が前月に混ざる）

**絞り込みは作物名で行う**（`crop_id` ではない）。マスターに無い作物（自由入力）も
同じ名前でまとまってほしいのと、同じ作物を別の年に作っても横断して見たいため。
栽培詳細の「収穫 ›」からは、その栽培だけに絞ったアルバムへ飛ぶ。

### S05 カレンダー / S06 ギャラリー（R05 / WBS 2.3）

どちらもホーム右上のアイコンから開く。**タブには出さない** — 振り返るための画面で、
毎日使うものではないため。

#### カレンダー

作業ログと収穫を月グリッドで見る。日を選ぶとその日の記録が下に出る。

**点は「作業」「収穫」の 2 色だけ。** 作業種別ごとに色を割り当てる案もあったが、
1 マスが 40px 前後しかなく、色を増やすと判別できない。
栽培の件数を点の数で表す案は、凡例の「緑=作業 / 橙=収穫」と衝突して読めなくなった
（実機で確認して撤回）。種別は日を選んだときの一覧で読める。

引くのは**表示中の月だけ**。全期間を引くと記録が増えたときに開くのが遅くなる。

#### ギャラリー

菜園の写真をぜんぶ 1 本に並べる。作業ログの写真も収穫の写真も混ぜ、
収穫には角に暖色の印を置く。

アルバム（S04）が月別グリッドなのに対し、こちらは**日付で区切らない密なグリッド**。
「いつ撮ったか」ではなく「どんな写真があるか」を眺めるための画面なので、
見出しを挟まず 1 画面に多く入れる。収穫だけ見たいときは収穫タブへ。

### S07 お知らせ（リマインダー）（R11 / WBS 2.4・2.5）

栽培詳細の「お知らせ」欄から設定する。通知を押すとその栽培の記録画面まで連れて行く
（見ただけで終わると記録が残らず、リマインダーの意味が薄れる）。

**「毎日」を既定にしている。** 日数指定（N日おき）は OS に該当する繰り返しトリガーが
無く、次の 1 回だけ予約して起動時に積み直す方式なので、**アプリを長く開かないと
止まる**。迷ったときに選ばれる位置には、止まらない方を置く。フォームでもその旨を書く。

**「必ずこの時刻に鳴る」とは書かない。** Android の Doze 下では数十分ずれうる。
水やりの声かけに秒精度は要らないので許容し、フォームに
「端末の省電力の状態によっては、数十分ずれて届くことがあります」と添える。

終了した栽培には出さない。収穫し終えた株の設定を触れても通知は来ない
（`getActiveReminders` が終了分を外す）ので、出すと「設定できるのに来ない」になる。
