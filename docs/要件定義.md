## 1. プロダクト概要

**アプリ名:** さいえん手帳
**ストア表記案:** さいえん手帳 − 家庭菜園・栽培記録(ASO サブタイトルは Q1)
**サブタイトル案:** 育てて、記録して、ちゃんと採れる。家庭菜園の手帳とアドバイス
**対象プラットフォーム:** モバイル(Android 先行 / iOS)、だいどこと同じ Expo 構成
**対象ユーザー:** 家庭菜園・ベランダ菜園・市民農園・ハーブや草花を育てる個人と家族

### 製品の 3 本柱

1. **記録** — 作業ログ・写真・カレンダー(だいどこの記録体験の移植)
2. **収穫** — 写真で残す収穫の記録とアルバム。「今日の採れたて」を撮って積み上げる。数量を添えれば統計にもなる
3. **アドバイス** — 栽培暦・作物ガイド・「次の作業」提示・AI 相談で、初心者でも失敗しない

### だいどことの関係

- 「ローカルファースト + 記録中心」のコンセプトを園芸ドメインに移植
- リポジトリを fork し、DB 基盤・通知・写真・課金・広告・AI 推論パイプラインを流用(§7)
- ブランド・ストア掲載・収益化は独立。だいどこ本体には影響を与えない

## 2. 問題定義

### 解決したい課題

GreenSnap 等の既存園芸アプリは SNS・観賞植物寄りで、「自分の菜園を管理・記録して成果につなげる」体験に特化したものが乏しい。

- 何をいつ植えたか・いつ追肥したかを忘れる(手帳やメモアプリでは続かない)
- 水やり・追肥・防除のタイミングを逃す
- **次に何をすべきか分からない**(芽かき? 追肥? 収穫はいつ?)— 初心者が挫折する最大の理由
- **収穫の成果が残らない**ため達成感が積み上がらず、翌シーズンへの意欲につながらない
- 去年の反省(播種が遅い、肥料過多)が翌シーズンに活きない
- 同じ区画に同じ科を植えて連作障害を起こす
- 病気・害虫が出たとき、名前も対処も分からない

### 影響を受けるユーザー

- 家庭菜園・ベランダ菜園をしている 30〜60 代(園芸人口は中高年層が厚い)
- 市民農園の区画を借りている人
- 子どもと一緒に野菜を育てる家族

### 放置した場合のコスト

栽培の経験知が蓄積されず、毎年同じ失敗を繰り返して挫折する。「今年もうまくいかなかった」で園芸自体をやめてしまう。

## 5. ユーザーストーリー

### 5.1 栽培管理

- 栽培者として、植えた野菜・草花を品種・場所・植え付け日付きで登録したい。そうすれば「今なにを育てているか」が一覧できるから。
- 栽培者として、プランター・畝・区画など「場所」を管理したい。そうすればどこに何が植わっているか分かり、来年の連作回避にも使えるから。
- 栽培者として、去年の栽培記録をアーカイブとして振り返りたい。そうすれば今年の植え付け時期や品種選びに活かせるから。

### 5.2 作業記録

- 栽培者として、水やり・追肥・剪定・防除などの作業を 1 タップで記録したい。そうすれば続けられるから。
- 栽培者として、作業記録に写真とメモを添付したい。そうすれば生育の変化を振り返られるから。
- 栽培者として、同じ植物の写真を時系列で見比べたい。そうすれば育ちの良し悪しが分かるから。

### 5.3 収穫

- 栽培者として、今日の収穫をその場で**写真でパッと記録**したい。そうすれば手間なく成果が残るから。(数量入力は任意)
- 栽培者として、収穫写真が並ぶ**収穫アルバム**を眺めたい。そうすれば「これだけ採れた」を実感できて、来年も続けたくなるから。
- 栽培者として、余裕があれば数量(個・g・束)も添えたい。そうすれば作物ごと・月ごとの集計も見られるから。(P1)
- 栽培者として、収穫適期の目安を教えてほしい。そうすれば採り遅れ・採り忘れを防げるから。

### 5.4 アドバイス

- 栽培者として、地域(寒冷地/中間地/暖地)に合った「今月の菜園仕事」を見たい。そうすれば種まき・植え付けの適期を逃さないから。
- 栽培者として、育てている栽培ごとに「次にやるべき作業」(そろそろ芽かき、植え付けから 3 週間なので追肥、など)を教えてほしい。そうすれば初めての野菜でも迷わないから。
- 栽培者として、作物ごとの基本の育て方(株間・水やり頻度・よくある失敗)をアプリ内で読みたい。そうすれば検索して回らなくて済むから。
- 栽培者として、水やりや追肥の繰り返しリマインダーを設定したい。そうすればタイミングを逃さないから。
- 栽培者として、葉の写真から病気・害虫を判定し対処を知りたい。そうすれば早く手を打てるから。(AI)
- 栽培者として、生育の状況(写真+状況説明)をもとに個別のアドバイスがほしい。そうすれば「葉が黄色いのは肥料切れ?水のやりすぎ?」に答えが得られるから。(AI)

### 5.5 資材・買い物

- 栽培者として、種・肥料・薬剤・土などの資材在庫を管理したい。そうすれば二重買い・切らしを防げるから。
- 栽培者として、資材が減ったら買い物リストに載せたい。そうすれば店やネットでまとめて買えるから。

## 6. 機能要件

「流用元」は だいどこ の実装資産(§7 参照)。

### 6.1 Must-Have(P0 = v1.0 までに必須)

#### 栽培管理

- **R01** 栽培(植え付け)の CRUD
  - 受け入れ基準: 作物名・品種・場所・植え付け日(種/苗の別)・写真・タグ・メモを保存できる。栽培終了(収穫完了/枯死)でアーカイブできる
  - 受け入れ基準(追加 2026-08-10): **すでに育てている株を、植えた日にさかのぼって登録できる。** 相対日付(1週間前/1か月前/3か月前)を 1 タップで選べ、選んだ時点の経過日数が画面に出る
  - なぜ: アプリを入れる前から育てているものが必ずある。既定の「今日」のまま保存されると経過日数がずれ、R10「次の作業」の追肥・収穫の目安まで狂う
  - 流用元: recipes CRUD(版管理は削除)
- **R02** 場所(区画)管理
  - 受け入れ基準: プランター/畝/区画を作成し、栽培に紐付けられる
  - 流用元: なし(新規・小規模)
- **R03** 栽培一覧・検索
  - 受け入れ基準: 栽培中/アーカイブの切替、作物名・タグ・場所で絞り込み
  - 流用元: レシピ一覧 + FTS5 検索

#### 作業記録

- **R04** 作業ログ(「やった!」)
  - 受け入れ基準: 作業種別(水やり/追肥/植え替え/剪定/防除/収穫/その他)を 1〜2 タップで記録。日時自動設定。写真最大 6 枚・メモ添付可
  - 受け入れ基準(追加 2026-08-10): **付け忘れた作業と、ギャラリーにある過去の写真を、さかのぼって記録できる。** 相対日付(昨日/3日前/1週間前)を 1 タップで選べる。収穫記録(R06)も同様
  - なぜ: 記録は毎日つけられるものではない。クイック記録(詳細画面のボタン)は常に「今」で保存するので、さかのぼりはフォーム側の担当として明示する
  - 流用元: cooking_logs / cooking_photos + timeline.service
- **R05** タイムライン・カレンダー・ギャラリー
  - 受け入れ基準: 作業ログを時系列/月グリッド/写真一覧で閲覧できる。カレンダーは作業種別・栽培ごとに色分け表示できる
  - 流用元: calendar.tsx / gallery.tsx / timeline.service ほぼそのまま

#### 収穫(中核機能)

- **R06** 収穫記録(写真中心)
  - 受け入れ基準: 「収穫」ボタン → カメラ/写真選択 → 保存、の最短 3 タップで記録できる。数量+単位(個/g/kg/束/株)は**任意入力**(作物ごとに既定単位を持つ)
  - 流用元: cooking_logs / cooking_photos 拡張
- **R07** 収穫アルバム
  - 受け入れ基準: 収穫写真を月別グリッドで一覧できる。作物・栽培でフィルタできる。栽培詳細にもその栽培の収穫写真が並ぶ
  - 流用元: gallery.tsx の絞り込み版

#### アドバイス(中核機能)

- **R08** 栽培暦「今月の菜園仕事」
  - 受け入れ基準: 作物 × 地域帯(寒冷地/中間地/暖地)の種まき・植え付け・収穫適期マスターを持ち、ホームに「今月まける種・植えられる苗」を表示できる
  - 流用元: なし(新規マスターデータ。初期 30 作物、Q3)
- **R09** 作物ガイド
  - 受け入れ基準: 作物ごとに基本情報(株間・日当たり・水やり頻度・追肥タイミング・収穫目安日数・よくある病害虫と失敗)を閲覧できる。R08 と同一マスター
  - 流用元: なし(新規)
- **R10** 「次の作業」アドバイス
  - 受け入れ基準: 栽培ごとに植え付け日からの経過日数と作物ガイドを突き合わせ、「そろそろ追肥(植え付けから 21 日)」「収穫適期に入りました」を栽培詳細とホームに表示。タップで該当作業の記録画面へ
  - 流用元: なし(新規のルールエンジン。低在庫通知の「チェック → 通知 → 深いリンク」パターンを踏襲)
- **R11** 繰り返しリマインダー
  - 受け入れ基準: 栽培ごとに「毎日 7 時」「3 日ごと」等の水やり・追肥リマインダーを設定・停止できる。通知タップで該当栽培の記録画面へ遷移
  - 流用元: notification.service(権限・チャンネル・タップ導線)。**繰り返しスケジュールは新規実装**

#### 資材・買い物

- **R12** 資材在庫 + 低在庫通知 + 買い物リスト
  - 受け入れ基準: 種・肥料・薬剤・土・道具をカテゴリ付きで在庫管理。閾値割れで通知 → 買い物リストへ一括追加
  - 流用元: pantry_items / shopping_items / low-stock.service ほぼそのまま

#### データ

- **R13** ローカル DB + バックアップ
  - 受け入れ基準: 全データがオフラインで動作・保持される。DB+写真の zip バックアップ/復元
  - 流用元: expo-sqlite + Drizzle + backup.service

### 6.2 Nice-to-Have(P1 = v1.5)

- **R14** AI 写真診断: 写真 → 品種推定 / 病害虫診断(Gemini Vision)
  - 流用元: recipe-photo-inference パイプライン + freemium(無料 1 回/日 + 広告ボーナス + BYOK 無制限)をそのまま踏襲
- **R15** AI 栽培相談: 写真+状況説明(「下葉が黄色い」) → 原因候補と対処のアドバイス。診断と同じ無料枠を消費
  - 流用元: 同上(プロンプト・出力スキーマ新規)。免責表記必須(Q5)
- **R16** 成長比較ビュー: 同一栽培の写真を定点比較(2 枚並べ・スライダー)
- **R17** 連作障害チェック: 区画に新規植え付け時、過去 2〜3 年の同じ科(ナス科・ウリ科等)の履歴があれば警告
- **R18** 収穫統計・年間サマリー: 数量が入力された収穫の作物別・月別集計と、年末の振り返り(作物別ランキング・初収穫日・収穫写真のハイライト)。数量入力は任意のため、写真だけでも成立する「今年の収穫アルバム」を基本形とする

以下 R25〜R28 は競合体験の取り込み(docs/ペルソナ・競合分析.md §4)。対象フェーズは **v1.6 春支度**(春の獲得期 2〜5 月に向けた強化)。

- **R25** 作付け計画(予定と実績): 「今年植えるもの」リストと植え付け予定日を登録し、ホーム・カレンダーに予定表示、時期接近で通知。計画から栽培登録へワンタップ変換(菜園ナビの予定/実績・紙の年間栽培計画表に相当)
- **R26** ケアスケジュール自動提案: 栽培登録時、作物ガイドの水やり頻度・追肥タイミングからリマインダーの既定スケジュールを自動提案(Planta のケアスケジュールに相当)
- **R27** 「去年の今ごろ」: ホーム・栽培詳細に前年同時期の記録・写真カードを表示(『やさい畑』の「菜園 2 年手帳」の比較体験のデジタル版。2 シーズン目継続=G5 の要。初年度はデータが無いため空状態設計に注意)
- **R28** 収穫カードの共有: 収穫写真+作物名+日付の共有用画像を生成し、OS シェアシートで SNS 等へ書き出せる(コミュニティを持たずに共有欲求に応える。獲得チャネルも兼ねる)

  - 補足(2026-08-03 レビュー): 園芸用品は EC での購入も多いため、**注文確認画面のスクリーンショットからの読み取り**も対象にする。撮影経路は既に対応済み(receipt 画面がカメラとギャラリーの 2 系統を持ち、ギャラリーはスクショを含む)が、`receiptParser.ts` が紙レシート前提のヒューリスティック(合計/小計/税の行を除外、行末価格を抽出)のため EC 画面ではパースが合わない。着手時にパーサ拡張と AI(R14/R15 の基盤)への委譲を比較する

以下 R32〜R33 は継続利用(G5: 2 シーズン目の継続)を狙う機能案。**実装判断は先送り**で、優先度は着手時に再評価する。

- **R32** 日次定点撮影 + 週次 AI レビュー: 毎日同じ栽培を 1 枚撮る習慣を促し(前日写真のゴースト表示・撮影リマインダー)、週に一度、その週の写真と作業ログをまとめて AI が振り返る。単発の相談(R15)ではなく**時系列の変化**に対する助言(「先週より葉色が薄い。追肥の時期」)を返すのが差分。R16 の定点比較は人が目視で比べるところまでで、AI は介在しない
  - 依存: R14/R15 の AI 基盤、R16 の定点撮影 UI
  - 論点: 週次バッチの推論コスト(無料枠の設計が都度課金前提のため要再設計)、写真が揃わない週の扱い、通知頻度
- **R33** 定植・植え替えの適期通知: 種まきからの経過日数・本葉の枚数・気温をもとに、鉢上げ/定植/植え替えの適期を個別の栽培ごとに通知する。R08 の栽培暦が「今月の一般的な作業」なのに対し、こちらは**その株の状態と地域に紐づく**個別提案
  - 依存: R09 作物ガイドのマスターデータ(株間・生育日数)、R20 の気象データ
  - 論点: 判断材料をどこまでユーザー入力に頼るか(本葉の枚数を毎回聞くのは continuity を下げる)

## 7. fork 方針と流用マッピング

### 7.1 fork 手順の方針

- だいどこリポジトリを fork(コピー)し、パッケージ名・アプリ ID・ブランドを差し替える
- 共通 packages の切り出しは**しない**(両アプリの独立進化を優先。将来往来が増えたら再検討)
- **fork 直後に削除する機能:** URL 取り込み / OCR 取り込み / バーコードスキャン / レシート読み取り / AI 名寄せ辞書 / レシピ版管理 / 料理中モード・タイマー
- **残す基盤:** DB・マイグレーション基盤、通知、写真(撮影・圧縮・保存)、タグ、FTS5、カレンダー/ギャラリー/タイムライン、在庫⇄買い物、バックアップ、freemium(usage + RevenueCat + AdMob)、AI Vision サーバー/BYOK、UI キット、コーチマーク

## 8. 収益化要件

### 8.1 方針

v1 はだいどこと同じ **広告 + フリーミアム課金** の 2 本柱。アフィリエイトは**後回し**(v2.0 以降に §8.5 の設計で再開)。

### 8.2 広告(AdMob) — 流用

- リワード広告: AI 診断・AI 相談の無料枠追加(トークン制)
- アプリ起動広告: 頻度制限付き
- 園芸は春(3〜5 月)・秋(9〜10 月)に利用が集中するため、収益もシーズナリティを持つ前提で計画

### 8.3 課金(RevenueCat) — 流用

- プレミアム: AI 診断・相談無制限 + 広告非表示(だいどこのフリーミアム設計を踏襲)
- BYOK(Gemini キー持ち込み)は無料で無制限(だいどこ踏襲)

### 8.4 法務・ポリシー上の注意

- **農薬:** 農薬取締法上、適用作物・希釈倍率を誤った使用推奨はリスクがある。AI 診断・作物ガイドとも「病名 + 一般的な対策情報」に留め、特定農薬の使用指導はしない
- **AI アドバイスの免責:** 診断・相談結果は参考情報である旨を明示(Q5)

### 8.5 (凍結)アフィリエイト設計メモ — v2.0 以降に再開

> 2026-07-27 調査分。再開時にこの節から着手する。

- トリガー設計: 栽培暦(月・地域) / 植え付けイベント / 作業ガイド / 低在庫 / AI 診断結果 → 「いま必要なもの」だけを出す。汎用バナーは貼らない
- **v2 開始時は楽天アフィリエイトから**。[広告掲載基準](https://affiliate.rakuten.co.jp/guideline/adrule/)にアプリ掲載を明示的に禁じる規定はないが、アプリ内掲載可否は公式サポートに事前確認(Q7)
- **Amazon アソシエイトは[モバイルアプリでの利用に別途審査・承認が必要](https://affiliate.amazon.co.jp/help/node/topic/GHBY6W8UPTEFD3ZX)**。アプリの実績ができてから申請
- 商品リンクは外部ブラウザで開く。「広告/PR」ラベル必須(ステマ規制)。設定で OFF 可
- 収益試算: MAU 1,000 で月 1,000〜2,000 円程度。MAU 1 万超えから意味が出る

## 9. 非機能要件

| 項目           | 要件                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
